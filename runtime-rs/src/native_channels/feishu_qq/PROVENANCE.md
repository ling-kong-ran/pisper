# Adapter protocol provenance

Feishu frame tags, message conversion behavior, send fallback classification and registration parameters are derived from the installed, locked `@larksuiteoapi/node-sdk` version1.72.0. Its MIT notice is preserved in `LARK-SDK-LICENSE`. `sdk-oracle.json` was generated by executing that actual SDK under Node v24.19.0; it contains synthetic credentials and synthetic events only. The generator is saved at `release/local-rust-build/channels-feishu-qq/oracle.mjs`.

QQ default gateway behavior is derived from the read-only release commit `582160235671903d9f1c7034b457557b1df74b68`. `qq-wrapper-oracle.json` is actual release-wrapper output, generated without public requests by `release/local-rust-build/channels-feishu-qq/qq-wrapper-oracle.mjs`.

The QQ onboarding wire protocol was inspected in the installed `@tencent-connect/qqbot-connector` version1.2.0, whose package declares UNLICENSED. Its source is neither included nor invoked in production. The native implementation uses standard AES256-GCM through the reviewed `aes-gcm` crate; the actual connector decrypts a synthetic golden fixture during development. No opaque JavaScript bundle or ordinary Node process is shipped by these adapters.

Explicit limitations and verification scope are recorded in the ignored `release/local-rust-build/channels-feishu-qq/verification.json` and `REPORT.md`. Nondefault QQ protocol helpers are excluded from release-parity claims.
