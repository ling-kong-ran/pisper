# 可复用工作流与游戏精灵图

工作流保存处理步骤和输入定义。每次点击“运行”，先填写本次输入；运行值作为该次运行的快照保存，不会改写模板。内置模板和空白模板默认提供“本次任务”“参考材料”“约束与输出要求”。旧的无输入定义工作流也可以补充本次任务。

在触发器的输入编辑器中添加字段，配置变量名、显示名称、说明、类型、默认值和必填。支持短文本、长文本、数字、开关、图片、视频。节点的“处理规则”引用 `{{inputs.task}}` 等变量，点击变量按钮可插入；前序结果可用 `{{previous.summary}}`，指定节点结果可用 `{{nodes.nodeId.output}}`。变量只作文本替换，不执行表达式；缺少必填值、重复/保留变量名或不存在的引用会明确报错。

## 图片与视频输入

文字和媒体共用输入组件。图片支持 PNG/JPEG/WebP，最大 8 MiB、边长 4096 像素、总像素 1600 万；视频支持 MP4/WebM，最大 64 MiB。可以在模板里设置默认素材，也可以在每次运行时替换。输入中保存受控素材 ID，不接受客户端提供任意文件路径。

图片作为 Agent 图片附件传递。视频作为本机受控文件引用交给节点使用文件/媒体工具处理，并不意味着所有模型都具备原生视频理解能力。限制工作区访问的节点仍遵守原来的文件权限；访问工作区外素材可能需要用户调整工作目录或访问模式。

## 游戏精灵图生成：普通画布模板

在列表或模板里点击“游戏精灵图生成”，直接进入工作流画布。画布负责组合步骤；“更多工具 → 游戏素材工作台”是独立工具，拥有自己的项目和生成任务，只与工作流共享底层图像插件。

默认图是：图片输入 → 四条动作分支（动作生成 → 去背景 → 拆帧 → 裁边/对齐）→ 动画预览 → 图集输出。节点库还提供区域修补，可拖入或点击添加。每个节点都能改名、复制、删除、修改参数或重新连线；可以只保留一个动作，也可以添加跳跃等自定义动作。

1. “图片输入”节点指定本次输入的图片字段。运行时上传图片、填写角色/风格约束，不把某次素材写死在处理步骤里；需要时可保存默认素材。
2. “动作生成”节点选择图像模型、动作、方向和帧数。默认待机呼吸、走路、跑步、攻击，每动作八方向、每方向4帧。**默认合计32次图像请求**，运行表单会显示数量；可以先只选一个方向调试。
3. 每次生成只处理一个动作、一个方向，采用 FrameBaker 的少量连续帧提示词与网格策略；保留上传图风格、身份、装备和比例，要求固定相机、完整角色、逐格连续动作和首尾循环。每张图真正携带参考图片，不仅是文字描述。
4. “去背景”提供多色键、容差、软边、边缘连通与可选本地模型；“拆帧”读取生成网格或用户指定网格；“帧处理”控制透明边、统一底部对齐、留白、顺序、时长和逐帧平移/旋转/缩放/透明度。
5. 最大帧边长默认256像素，仅等比例缩小、不放大小图，使真实模型的大尺寸输出能组成有界的图集。最终预览支持动作/方向筛选、播放/逐帧、洋葱皮与处理前对比；输出PNG及JSON帧坐标/时长。

调整处理参数后，可以点击“仅运行此节点”，复用上一次有效上游输出，不重新调用前面的图像模型。上游参数改变或结果失效时，需要先重跑上游；单跑节点会使下游旧结果失效，按顺序继续运行预览和输出即可。动作生成失败时保留已经成功的方向；参数不变的手动续跑只请求缺失方向，不自动重试收费调用。

FrameBaker 不是能够从一张图保证推导正确八向动作的独立模型。它的生成仍依赖外部模型/CLI，少量分批、参考图约束、拆帧和编辑帮助提高可控性，不能自动证明角色姿态正确。本次直接移植了它的动作提示词、网格推荐、多色键/色盘、透明范围、几何与图集布局代码；完整来源和MIT许可见 [供应商记录](../shared/vendor/framebaker/README.md)。骨骼分件绑定、Qwen场景分层、ffmpeg视频抽帧没有被宣称为本次节点实现。

## 可选本地算法

安装包不包含算法大文件，打开页面不会自动下载或运行。点击“下载算法”后缓存资源；运行对应节点才在 Runtime 创建短命 Worker，完成、取消或关闭后释放；离开页面不停止已开始的工作流。

算法、模型和许可证全部通过 CDN 下载，不直连 GitHub。模型使用官网分发同类的 `gh-proxy.com` 加速入口和 `ghfast.top` 备用源；JS、WASM 及许可证使用 jsDelivr。每个来源都必须通过相同的长度与 SHA-256 校验，失败时显示具体文件和网络、超时、校验或存储原因。无法联网时可在其他机器下载后通过 ZIP 携带完整依赖。

| 操作 | 实现 | 资源约大小 | 许可证 |
| --- | --- | --- | --- |
| 本地去背景 | U²-Net small (`u2netp`) + ONNX Runtime Web 1.20.1 | 15.9 MB | U²-Net Apache-2.0；ORT MIT |
| 区域修补/去水印 | OpenCV.js 5.0.0-release.1 Telea inpainting | 13.3 MB | Apache-2.0 |

工作台上传图片的“本地去背景”默认使用 U²-Net 前景识别，适合人物与复杂背景。未安装时在图片下显示下载入口与大小，用户点击后才下载，之后可离线处理；不会静默改用按颜色移除。每次去背景从上传的原图重新处理，避免对已经误删的结果反复抠图，并保留“恢复原图”。

纯色背景可显式选择无依赖的颜色移除；主体与背景同色时可能误删，不能用它代替复杂背景的前景识别。生成管线要求模型输出统一纯色背景，因此其节点继续使用颜色移除。区域修补使用 OpenCV，按百分比设置选区，只改变选区 RGB 并保留透明度。这些处理不调用收费图像生成服务。模型和 OpenCV 在独立线程串行运行，避免多个并行节点同时驻留模型。

资源来源、固定版本、字节数、SHA-256、许可证和 MIME 是 [`shared/sprite-engine-catalog.mjs`](../shared/sprite-engine-catalog.mjs) 的单一来源。模型来自 [rembg 的固定资源发布](https://github.com/danielgatis/rembg/releases/tag/v0.0.0)，算法来自 [U²-Net](https://github.com/xuebinqin/U-2-Net)；推理运行时来自 [ONNX Runtime](https://github.com/microsoft/onnxruntime/tree/v1.20.1/js/web)；修补实现来自 [OpenCV.js](https://github.com/TechStark/opencv-js/releases/tag/v5.0.0-release.1)。下载和导入都核对全部摘要，不执行任意包内脚本。更新资源须同时更新目录版本、全部文件摘要和许可证，并重新执行实际 WASM 验收。

## ZIP 导入、导出与内网使用

文件导入导出只使用 `.zip`，不提供旧 JSON 文件导入兼容入口。

- 统一工作流包包含DAG、节点设置、输入定义、默认图片/视频及所需的已下载本地算法完整资源和许可证。色键、拆帧和帧变换不额外下载模型。
- 导入分配新的工作流和素材ID，清空原机器工作目录，保存为草稿，不自动运行。缺少图中必需的已下载算法时先补齐依赖再导出，避免带到内网才发现缺文件。
- API Key、连接凭据和原机器工作目录不随包导出。外部聊天/图像模型、MCP 服务、Skill 和通知渠道通过清单提示，在目标机器另行配置；压缩包不能将远程服务变成离线服务。图像生成仍需能访问的图像模型。
- 包最大 128 MiB（压缩前后均限制），最多 300 文件，单文件最大 64 MiB。缺文件、摘要不符、路径穿越、重复路径、符号链接、加密 ZIP 和异常解压尺寸会被拒绝。

## 验证入口与平台范围

`npm run check`、`npm test` 和 `npm run build` 覆盖类型、翻译、单元/协议、生产资源和体积预算。`npm run test:workflows:ui` 使用临时 Runtime 和确定性图片响应，检查完整上传/生成/预览以及移动尺寸布局；已加入 `npm run test:ui`。

要额外验证真实 U²-Net/ONNX 与 OpenCV，先把目录清单中原始资源下载到独立测试缓存，设置 `PISPER_TEST_SPRITE_ENGINE_DIR` 后运行该 UI 测试。测试校验摘要、断网重导入和实际推理，不读取用户模型凭据，不调用付费外部模型。

`npm run test:workflows:ui -- --dev` 使用隔离的 Vite 开发服务器运行同一流程，覆盖开发模式的 Worker 和资源加载。

前端与 Runtime 接口适用于共用 Web 客户端；图像处理在服务端 Node Worker/WASM 执行。移动尺寸浏览器测试不等于 Android/iOS 真机测试，平台构建、真实 WebView 性能和设备内存另行验收。TUI 继续使用 JSON 工作流运行协议，本次没有新增 TUI 图像预览命令。

## 游戏素材工作台与编辑器布局

“更多工具 → 游戏素材工作台”是内置自定义组件 `pisper-game-asset-workbench`，可在界面设置的组件列表中管理。它通过受限 `gameAssets` 桥上传参考图、保存独立素材项目、启动/停止生成、预览并下载图集。它不创建或修改工作流，也不随工作流画布变化而变为只读。工作流 ZIP 仍只在工作流列表导入导出。

生成后点击手动调帧，可逐帧选择、查看洋葱皮、拖移位置、修改缩放/旋转/透明度/时长、排序/复制/删除、擦除或恢复透明区域，并撤销/重做。保存编辑会从原始帧重放操作并重新导出图集；不会调用图像模型。未保存的编辑留在当前编辑器草稿中。

工作流和工作台都无需开启 Agent 插件。插件设置中的 `image_assets` 仅控制 Agent 是否获得图像能力，默认关闭；开启后每次调用仍校验最新开关。关闭不会影响用户在工作流或工作台中的操作。

Agent 使用 `export` 时，会将图集 PNG 和帧信息 JSON 保存到当前工作目录的 `generated/image-assets/` 下，每次使用独立子目录，不覆盖已有文件。工作台仍通过下载按钮导出，工作流仍使用自己的节点结果与 ZIP。

未来视频工作台可以复用组件承载与受控桥模式，拥有自己的任务与项目；其处理能力通过独立领域插件提供，避免绑定到工作流的状态和生命周期。
