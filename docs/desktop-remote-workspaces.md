# 桌面主动连接远程 Linux 工作区

状态（2026-09-27）：实现、源码回归及 Windows Tauri → WSL Linux 实际任务验收通过；正式发行打包和安装版验收待完成。

## 使用方法与边界

1. 在 Linux 上运行 Pisper Runtime，进入「设置 → 远程访问」启用 HTTPS。
2. 生成配对二维码，展开「手动连接所需信息」，复制 HTTPS 地址和证书指纹，并通过可信渠道核对指纹。
3. 在 Windows 桌面主窗口的「设置 → 远程访问 → 连接到 Linux 工作区」填写上述信息和配对码，点击「配对并打开」。
4. 在独立远程窗口选择 Linux 工作目录、创建会话和执行任务。以后可直接从保存的连接重新打开，无须再次配对。

现有「远程访问」是入站服务，不等于桌面主动连接 Linux。新增连接保留安装包内的 ZCode 风格前端，
在已运行 Pisper Runtime 的 Linux 上操作真实会话、文件与 Agent 工具。这不是 SSH 安装器；不自动安装
远程软件，不读取或上传本机 Provider 密钥，也不把远程 API 失败降级为本机执行。

关闭窗口不会停止 Linux 上的任务。「移除」会关闭该连接的本机窗口并删除本机保存的档案；不删除远程
文件或会话，也不吊销设备授权。需要吊销时在 Linux 的远程访问页移除设备。

## 归属与依赖

没有文件搬迁，既有 HTTP/SSE 数据与配对响应保持兼容。新增本机专用的
`GET /api/remote/connection-info` 返回手动连接所需的指纹和 HTTPS 端点；带有远程身份的请求一律返回 403。
旧 Runtime 不提供该端点时，二维码配对仍可用。

- `src/features/config/RemoteWorkspaceSettings.tsx`：配置页内的主动连接表单、连接列表与移除确认。
- `src/types/remote-workspace.ts`：不含凭据的原生桥接契约；配置 Feature 不拥有设备令牌。
- `src-tauri/src/desktop_shell/remote_workspaces.rs`：桌面配对、档案和远程窗口生命周期；只允许已认证的本机 main 窗口调用。
- `src-tauri/src/loopback_access.rs`：随机一次性引导、端口独立 Cookie、同源/Host 与规范路径校验；与业务 UI 解耦。
- `src-tauri/src/mobile/{pairing,pinning,proxy,store}.rs`：复用平台无关传输实现，保留移动端入口；desktop 调用新增的固定档案代理入口。文件位于 mobile 下是历史归属，不为重命名搬迁整套移动生命周期。
- `desktop-remote` capability：仅 main 可调用；`remote-*` 窗口不注入本机桌面桥接，不授予 Tauri 原生权限。

本机主窗口继续连接原 sidecar。每个远程窗口使用独立源、Cookie 和内存档案快照，HTML/JS/CSS 从本机
安装包提供，`/api/*` 固定转发给该远程服务器。剥离调用方凭据和上游 Set-Cookie；失败不回退本机。
禁止歧义路径经 URL 规范化进入本机 API；禁用本机资源重定向。关闭原生窗口时释放回环监听器和长连接，
不主动停止远端任务。断线恢复与应用重启重新连接均保留远程持久会话。

TLS 除固定证书指纹外，还验证 TLS 1.2/1.3 握手签名，不能仅凭复制公开证书认证。显式选用 ring provider，
避免桌面依赖同时启用 ring/aws-lc 时首次连接 panic；用独立进程测试覆盖无全局 provider 的冷启动。

- 完整 UI 流程通过：配对失败保留输入、配对成功清码、开窗失败保留档案、移除确认、普通 Web 隐藏入口、远程页不请求入站管理 API、手动连接信息与旧 Runtime 404 回退。

- QA 应用整体退出并重启后，从保存档案直接连接成功，无须重新配对；远程历史和本机基线不变。
- Linux 本机实际页面生成二维码、展示 HTTPS 地址和指纹，不依靠请求 mock。

确定性 Linux 测试 Provider 仅用于隔离验收，不使用或上传用户凭据；不把它描述为云端真实模型测试。
