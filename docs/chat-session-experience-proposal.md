## 判断与参考范围

Pisper 已有工作区分组、会话搜索、桌面 Dock 分屏、移动会话标签、消息虚拟化、工具活动和执行模式。当前问题主要是**用户在找会话、判断 Agent 状态、继续输入时，需要理解太多入口和例外**，同时部分操作的界面含义与实际行为不一致。优化应先让默认单会话流程清楚，再保留分屏等进阶能力。

## 目标布局

桌面默认只突出一个活动会话，保留 Dock 分屏作为主动选择的操作。布局分为三层：左侧会话导航；中间会话标题、状态、正文和输入区；右侧是当前活动会话的改动、文件、计划或浏览器等上下文。宽桌面首次进入默认展开右侧栏，用户可以关闭；关闭后正文获得完整剩余宽度。终端继续作为按需面板，不常驻挤压对话。右侧栏由会话页统一拥有，不嵌在每个 Dock 面板里；分屏时仍只有一块右侧栏，内容随活动会话切换。

| 场景 | 导航与会话 | 上下文与操作 |
| --- | --- | --- |
| 宽桌面窗口 | 左侧显示当前工作区与会话列表；中间以单会话为默认，允许用户主动打开 Dock 分屏。 | 改动、文件和计划按需打开，不在空会话里占位。 |
| 紧凑桌面窗口 | 侧栏可收起；会话标题、执行状态和输入框始终可见。 | 分屏能力不可用时，菜单只提供“打开”；右侧内容改为抽屉或标签。 |
| 手机与窄屏 Web | 一次只展示一个会话，顶部能返回完整会话列表；最近标签可横向滚动，但不能成为唯一导航。 | 不展示分屏动作；工具按用户偏好和可用宽度收纳到紧凑图标托盘，通过“自定义快捷方式”查看名称并调整；触控目标按至少 44px 验收。 |

响应式行为应依据现有 `compactDock` 与 `phoneViewport` 的能力判定统一实现，而不是让按钮可见后再悄悄降级。桌面分屏、手机单会话、Web 与原生移动壳共用会话规则，但各自使用适合平台的导航容器。

## 关键交互规则

1. **会话查找与管理。** 左侧默认呈现当前工作区和最近会话，明确提供“全部会话”和搜索入口。搜索覆盖完整目录，而非先截取最近项。列表行以标题为主，时间和运行状态为辅；未读、需要处理和改动量均由 Runtime 的明确数据来源投影，不能从颜色或局部 UI 状态推断。置顶、归档与恢复不删除会话内容；搜索仍可找到已归档会话。
2. **工作区操作。** 左侧导航提供“新建项目”按钮，选择已有目录后在其中创建首个会话，将项目加入导航；不会新建或覆盖磁盘目录。确认后清除搜索并展开目标项目，新目录沿用固定排序规则追加底部。最近列表保留每个未归档项目的入口及当前会话，其余会话行受最近条数限制。“项目”的数量、删除范围和确认文案必须基于完整工作区成员，独立于搜索词、最近条数和折叠状态。批量删除中途失败时，应明确告知实际成功与剩余数量；不能给出“项目已删除”的成功提示。长期方案可由 Runtime 提供工作区成员统计和受控批量操作。
3. **标题与导航。** 会话标题在头部和列表中都可找到重命名入口。保存后以服务端返回名称同步侧栏、历史页、Dock 标签和移动标签；沿用已实现的 120 字上限，键盘支持 Enter 保存、Esc 取消，失败保留输入并显示原因。关闭标签只关闭视图，不删除会话。
4. **正文与执行反馈。** 普通对话正文保持阅读主线；工具调用、长日志和子任务默认显示一句摘要，可展开完整信息。等待审批、运行中、取消、重试中、失败、已完成使用一套状态语义。需要用户操作的审批或提问卡直接出现在会话流中；短暂 API 错误在靠近输入区的状态行提供“重试”和“查看详情”，不让大段红色诊断占据正文。
5. **输入区。** 输入框和发送／停止按钮是第一层；模型、执行模式、权限和附件等工具统一使用紧凑按钮，用户可逐项选择常驻或收纳、调整顺序，也可全部常驻或全部收纳；空间不足只临时收纳尾部工具，变宽后自动恢复，不改写偏好。按钮通过提示与无障碍名称表达当前状态，收纳区复用同一控件；运行时追加或排队输入必须清楚表明将发生什么，且不丢草稿。没有配置模型时继续使用可关闭的引导，而不是强制遮挡会话。
6. **历史和触控。** 历史行以“打开”为主动作，重命名、归档、删除及桌面可用的分屏放进操作菜单；危险操作需准确描述范围。长历史采用分段加载或虚拟化，并保持搜索、焦点、键盘导航和列表滚动位置。

## 实施顺序与验收

| 阶段 | 范围 | 完成条件 |
| --- | --- | --- |
| P0：纠正含义错误的操作 | 修复项目批量删除的数据范围和确认结果；按实际布局能力隐藏或转换分屏动作。 | 30 条以上同工作区、跨工作区混排及搜索后删除都只作用于明确确认的完整范围；窄屏点击入口不会承诺分屏却只打开。 |
| P1：收敛默认会话体验 | 统一侧栏/历史导航；简化历史行；重排输入区；移动端提供完整会话入口并说明最近标签数量。 | 在 300px Dock 面板及 320/390/768/900/1280px 视口中，模型、模式、权限和主操作可识别；7 个以上手机会话均可找回；重命名后所有视图同步。 |
| P2：增强回顾与恢复 | 统一状态与重试；历史分段加载；在有稳定数据契约后加入置顶、归档、需要处理及改动摘要；按需上下文面板。 | 临时 API 失败、取消、重连、审批和后台任务均有明确下一步；1000 条历史仍能流畅搜索与滚动；桌面分屏及消息虚拟化无回归。 |

实现时由聊天领域拥有会话规则和公开接口，应用侧栏只消费这些接口；不要再形成可独立写入的多个会话目录副本。若新增归档、未读或状态字段，应先定义 Runtime 与 Web、TUI 的兼容协议和迁移。交互验证应覆盖键盘、读屏语义、中英文文案、触控，以及桌面 WebView、浏览器窄屏和原生移动入口。现有仅检查“四个分屏按钮存在”的源码守卫需要在同一阶段替换为按布局能力验证行为的测试。

## 输入工具栏偏好

默认恢复原有紧凑按钮，模型、权限和运行模式不再单独占一行。点击输入框的“+ → 自定义快捷方式”，可逐项常驻/收纳与排序，也可全部常驻、全部收纳或恢复默认。偏好仍由聊天领域的 `composer-toolbar-store.ts` 持有，保存在本客户端；窗口或 Dock 面板变窄只影响派生布局，不改变已保存的选择。

旧版完整 12 项布局保留位置和顺序；曾将模型、权限、运行模式移出偏好的 9 项布局只补回缺失的三个常驻按钮，其余自定义选择不动。Web、桌面与移动 WebView 共用此交互，不更改 Runtime/TUI 协议或原生桥接。验证覆盖偏好迁移、排序、批量切换和响应式分配，并在桌面/手机浏览器检查弹层与触控区域；原生设备验收另行执行。

## 字体与阅读层级

会话导航和常用控制统一使用常规（400）、中等（500）、半粗（600）三档：正文与会话列表用 400，项目、导航和操作标签用 500，页面及面板标题用 600。选中状态由既有底色和边线表达，避免切换时反复增粗；分组名称取消额外字距。Markdown 的语义加粗和代码等宽字体保持不变；行内代码与文件路径不再显示灰色底块和额外内边距，独立代码块继续保留原有底色、语法高亮和复制操作。

默认正文及输入区使用 15px，导航主标签 13px、辅助信息 12px；已有小／默认／大字体设置继续生效，正文分别为 14／15／16px。根元素与 Tailwind 的无衬线字体共用同一系统界面字体栈，由平台匹配中文、英文和标点；不再优先加载 Geist，也不强制覆盖浏览器的字体合成与抗锯齿策略。代码仍使用等宽字体，不新增字体下载。控件字体继承由 Tailwind preflight 负责，不再用未分层的全局 `font: inherit` 覆盖组件字号和字重。此次仅涉及共享前端样式，不改变会话数据、Runtime/TUI 协议或原生桥接。

浅色主题的正文、导航和辅助说明统一使用纯黑（`#000`），通过字号、字重与布局区分层级；深色主题保留高对比度亮色文字。聊天输入区单独使用更柔和的颜色：输入内容使用深灰、占位提示使用中灰，深色主题分别使用浅灰与中灰；不再让提示与已输入内容使用同一种颜色。其余原生输入框提示复用辅助文字色。历史活动行取消整行透明度，沿用背景区分最新活动。禁用态和语义状态色保持原有含义。
