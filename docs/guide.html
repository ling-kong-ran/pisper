使用教程

从安装到进阶：配置模型、并行推进多个 Agent、用分支比较不同方案，并在终端和手机上接着同一段工作。

安装 Pisper

桌面安装包自带 TUI 与 Runtime，无需预装 Node.js。

Windows

优先选择普通 -setup.exe；已有 WebView2 可离线安装，缺失时联网补齐。离线电脑缺少 WebView2 或无法确认时，选择包含该依赖的 -offline-setup.exe。两种包都不包含按需下载的语音模型。

macOS

仅支持 Apple Silicon：下载 .dmg，拖入「应用程序」。使用系统 WKWebView，无需额外内核包。尚未公证，首次打开见下方常见问题。

Linux

可选 .AppImage 或 .deb；AppImage 需先加可执行权限，可能需要 FUSE。离线部署需预先准备发行版所需系统库，DEB 可能依赖 WebKitGTK 等包。

用 npm 安装

已有 Node.js 20+ 时，也可以用 npm 安装命令行版本：

npm i -g pisper
pisper        # 启动终端 TUI
pisper web    # 打开 Web 前端与配置页

提示：npm 包只是安装器，会下载并校验签名后的 TUI 与 Runtime 组件，不包含桌面界面。

配置模型 Provider

Pisper 不内置模型，需要你自己的 Provider 和 API Key。请求由你选定的 Runtime 直连 Provider。

  1. 打开模型设置

    桌面端进入 设置 → 模型；终端中执行 /provider。

  2. 选择协议并填写凭据

    选择 Provider 协议，按需覆盖 Base URL，填入 API Key。Key 在界面中始终以掩码显示。

  3. 拉取并选择模型

    保存后刷新模型列表，为当前会话选定模型。保存与切换是解耦的，改配置不会打断正在运行的会话。

本地配置导入：模型设置页检测到可导入的 Codex 或 Claude 配置时，会显示一行提示。点击“查看”展开连接管理，再选择导入；应用启动时不再弹出导入提醒。

会话级模型：每个会话可以用不同模型。适合让便宜模型跑批量改动、贵模型做关键决策。

第一个会话

  1. 选择工作目录

    新建会话时指定项目目录。会话的文件读写与命令执行都以它为基准。

  2. 让 Agent 认识项目

    执行 /init，Pisper 会分析项目并生成或补全根目录的 AGENTS.md。已有的有效说明会被保留。

  3. 描述目标，而不是步骤

    直接说想达成什么。思考过程、工具调用和执行结果会分层展开，可随时折叠。

回复里提到的 .html 文件和 http://localhost:5173 这样的地址可以直接点，右侧浏览器会展开显示。 页面在沙箱里运行，读不到 Pisper 的数据。只能预览当前工作区内的文件，工作区外的路径会改为在文件管理器中显示； 用根路径（/assets/…）引用资源的页面，先启动开发服务器再打开它的地址。

在 macOS 和 Windows 桌面端，右侧浏览器是真正的浏览器窗口，GitHub、Google 这类拒绝被嵌入的网站也能打开。 可以开多个页签，切换时网页不会重新加载；切到“改动”等其他标签或换会话再回来时，当前页签会重新加载，其余页签点到时才加载。 网页里的新窗口和弹窗登录都开成新页签，登录状态保存在这个浏览器自己的数据里，不和 Pisper 共用。 macOS 上的下载会交给系统浏览器。Linux 桌面端、Web 版和手机上仍是内嵌预览，拒绝嵌入的网站要点“在浏览器中打开”。

在这两个桌面端，让 Agent 打开网站或测试网页时，它默认在右侧浏览器里操作：页面边缘会亮起，指针会移到它要操作的地方，页签上有机器人图标。 它用的是你在这里的登录状态，等于以你的身份读取和操作这些网站；审批规则照常生效，用完全访问时它不再询问，要留意。 切到别的标签或会话不会打断它。想让它停，停止这一轮或关掉它的页签都可以。其他环境里 Agent 用的是看不见的独立浏览器，不带登录状态。

需要操作没有接口的桌面应用时，Agent 可以用“电脑操作”：看屏幕、动鼠标、敲键盘。每个会话第一次用时会先问你。 开始后 Pisper 主窗口会最小化，把屏幕让出来，做完或需要你回答时再还原。Windows 上屏幕会盖一层半透明遮罩，按 Esc 立刻停止； macOS 和 Linux 上角落里有一个小窗口，点“停止”收回。它不能操作 Pisper 自己，同一时间只有一个会话能用。 macOS 第一次用要在系统设置里允许“屏幕录制”和“辅助功能”；Linux 目前只支持 X11，不支持 Wayland。可以在“功能 → 插件”里关掉。

语音输入 对话模式

并行会话与分屏

每个会话独享模型、上下文、工作目录与权限。

  • 分屏：拖动会话标签到窗口任意一侧，可上下左右四面分屏。
  • 同屏对比：让多个 Agent 用不同思路解决同一问题，进度同屏可见。
  • 跨会话直达：Ctrl + K 搜索并跳到目标会话或 Turn，自动载入历史并滚动到现场。
  • 同一文件夹里协作：几个会话（包括 Bot）改同一个文件夹时，Agent 写文件前会确认这个文件在它读过之后没被别人改过（隔壁会话、命令行、编辑器都算），改过就先重新读，不会把别人的修改整个盖掉；隔壁改了它用过的文件，它下一步就知道。输入框上方会提示还有哪个会话最近在这里改文件。
  • 会话之间留言：Agent 可以给同一文件夹里的另一个会话留言，商量谁改哪些文件。对方正在跑时下一步就读到；没在跑时留言显示在它的输入框上方，点「现在处理」或你下次在那边发消息时才交给它，不会自己开跑。
  • 回退不盖掉别人的修改：按轮回退文件时，之后被别的会话或程序改过的文件不回退，确认框里单独列出。

关于并行数量：并行会话都会真实消耗 Provider 配额，请按额度和速率限制安排。

Pisper Bot（实验功能）

Bot 是常驻的 AI 同事：一条一直开着的对话，加上它的设定（名字、头像、它负责什么、在哪台电脑从哪个目录开始、权限和工具）和它自己的记忆。它自己做快的事（读文件、查东西、小改动、跑短命令），长的、要你批准的派给子 agent 在后台去做，几件可以同时做，做完它在对话里告诉你结果。它从不让你干等：你什么时候说话，它都马上回。

  • 先打开开关：Bots 还在实验中，默认关闭。在 设置 › 实验功能 里打开 Bots，侧栏才会出现 Bots 分区；关掉后 Bot 和它们的会话都不再显示，记录保留，重新打开就回来。
  • 新 Bot 会先打招呼：新建后打开它的对话，它先介绍自己，并给你三件马上能定的事：每天的简报、盯一个项目（先选频率，默认每 6 小时只读看一遍，确认并选好目录后马上看第一遍）、连上聊天软件。简报和巡看每次都会消耗模型用量，可以在 Bot 设置里关；也可以不管这些卡片，直接在输入框说。
  • 点开就是它的对话：侧栏点一个 Bot，打开的是它那条一直在的对话；前面聊过的它都记得。它的头像随状态动，名字后的数字是它手上在做几件，悬停能看到正在做哪件。对话顶栏的设置按钮打开它的设定。
  • 派活，不占着对话：长的、多步的、要你批准的事，它派一个子 agent 去做，对话里出现一条“派了：…”，写着在做、用时，可以展开看进展、随时停下。同一个 Bot 同时做 3 件，多的排队；它会按活挑合适的模型。想补一句要求、想停掉哪件，直接对它说。
  • 随时插话：它在干活时你发一句，它马上停下这一步先回你，再接着做；它自己跑的命令超过 10 秒会转到后台接着跑（对话里一条“后台命令：…”），跑完把结果告诉你。要你拍板时它发一张问题卡片，选好后它接着做；“一小时后看下 CI”这类事它会给自己定个时，到点再做。
  • 网页和电脑操作它自己做：让它打开或操作网站，它用右侧浏览器（macOS、Windows 桌面端，其他环境是看不见的独立浏览器）；操作电脑上的应用用 Computer Use；还能启动已发布的工作流。这些活不能派给子 agent，所以就在对话里做。你在右侧浏览器里登录过的网站，它也是以你的身份操作。浏览器里的点击与填写、启动工作流、操作电脑都会先出现批准卡片；你发一句新消息就取消这次等待。操作电脑的批准只管这一轮，下一轮重新问。没人在场的一轮（定时、别的 Bot 叫起来、巡看和简报）不会弹卡片，它只告诉你它想做什么。“完全访问”档位的 Bot 不问这些。
  • 它自己的记忆：你让它记住的事、你纠正过的做法、做完一件活学到的，它记在自己的那份里，记下就生效。和当前这件事相关的会自动带上，派出去的子 agent 也一样。它还能只读你的全局记忆（设置页可关），Bot 之间互相看不到。在设置页能逐条看、改、删。
  • 它自己学会的：一件活做完，它会复盘：以后还会反复做的事，它把做法写成自己的技能，之后派出去的子 agent 都带着；你纠正过的做法也会更新进去。设置页的“它学会的”里能看全文、删掉，也能设成定时（比如“每周五照这个做一遍”）。
  • Bot 之间互相找：别的 Bot 负责的事，它会直接去找那个 Bot（比如让“测试”跑一遍回归）。对方的对话里出现这句话，写着是谁说的；对方用自己的子 agent、自己的权限去做，回话和做完的结果自动回到这边，时间线里一条“在等它回话”，回了就合上。为了不让两个 Bot 来回停不下来，同一件事最多来回 6 次，客气话不发，发得太频繁也会停下。
  • 主动（默认关）：在设置页的“主动”里打开后，它手上没活时会每隔几小时把它负责的东西只读看一遍（只读文件、搜索，不改东西、不跑命令、不往外发消息），发现写成对话里的一条建议，你说“做吧”它才去做；也可以让它每天定时写一份简报：过去一天做了什么、今天排了什么、有什么建议。“高级”里能改它同时做几件（默认 3 件）。
  • 设定每一轮都生效：它负责什么写进每一轮的系统提示，子 agent 的权限和可用工具（全部、只读或自定义）按设定执行；改了设定，下一件活就照新的来。Bot 从设定的目录开始干活，需要时也会去这台电脑上别的地方读写文件；不需要 git，也不另开分支。
  • 做不了才找你：新建的 Bot 默认“危险操作才问”，改文件、跑命令自己就做；只有命令守卫标出的危险命令（比如递归删除）、浏览器里的点击与填写、第三方插件，或者缺你才知道的信息、要你拍板时，才停下来问。子 agent 的批准卡片和提问出现在 Bot 的对话里，也会进“全部代理”和侧栏的“需要你”；一件活在等批准时，别的活照常做。想更严可以改成“每一步都问我”；能在群聊里叫它的 Bot 不能选完全访问。
  • 在聊天软件里叫它：在已连接的飞书、微信、QQ、Telegram 里用 /名字 要做的事 或 @Pisper 名字 要做的事 叫它，话进同一个会话；它说完把回复发回原来的聊天。中途要批准时，普通操作回一句 /名字 批准 或 /名字 拒绝 就行；/名字 状态 看它在不在忙。它正在说话时会回你“在忙”，等它说完再叫，或者在 Pisper 里接着说。
  • 定时让它做：定时任务的目标可以选一个 Bot，到点往它的会话里说一句；它正忙时，这句话排在这一轮之后。
  • 换台电脑干活：在另一台电脑上运行 pisper executor pair 配对后，Bot 可以在那台电脑上读写文件、跑命令。

实验功能：Bots 可能不稳定，之后的版本里也可能调整；遇到问题请在设置 › 实验功能里点“反馈”。

追忆分支与 Turn 标签

长对话会被压成主干与分叉视图。你可以在任意已完成的 Turn 上开新分支，源会话一字不改。

什么时候开分支

  • 想比较两种实现方案，又不想丢掉已经聊出来的上下文。
  • Agent 走偏了，希望回到岔路口重新给方向。
  • 需要保留一条“能用的版本”，同时继续激进尝试。

Turn 标签

给关键 Turn 钉上标签，作为可检索的锚点。标签绑定持久化边界，不依赖会过期的消息 ID，长会话里依然稳定。

工具、插件与 MCP

核心工具常驻上下文；扩展能力按需激活、用完即退，避免把上下文塞满。

想知道上下文被什么占了：点输入框的模型芯片，弹层里能看到系统提示词、项目说明、技能、内置工具、MCP、对话和工具结果各占多少。总量来自模型返回的用量，各部分是估算值。MCP 工具连上后不占上下文，调用时的参数和结果才算在 MCP 这一行。

类型 用途 激活方式
核心工具 读写文件、执行命令、检索代码 常驻，直接可用
本地插件 项目专属的自定义能力 描述需求后由 Pisper 生成、校验并安装
MCP 服务 结构化接入外部系统与真实数据 在 MCP 设置中配置服务端
技能 可复用的成套操作流程 按需加载，可自动触发

缺能力时直接说

不必先去找插件。描述你需要什么，Pisper 会编写、校验并安装本地插件，下一轮对话即可调用。

让其他 Agent 调用 Pisper

Pisper 可以连接外部 MCP 服务，也可以作为内置 MCP 服务供同一台电脑上的其他 Agent 调用。 服务默认关闭，在 Pisper 的 MCP 页面开启后，复制地址与令牌到支持 Streamable HTTP 和自定义 Authorization 请求头的客户端。

内置服务只监听本机回环地址。持有令牌的客户端可以读取会话与记忆、发送消息并调用已开放的工作流等能力； 会话内的工具继续遵守已有审批规则。请保管好令牌，需要时可在 Pisper 中轮换。

执行模式与审批模式

两个正交的开关，都在输入区工具栏上，随时可切换： 执行模式决定 Agent 怎么干活，审批模式决定它能触碰什么。

执行模式：Plan / Goal / Team

模式 工作方式 适用场景
Plan 按计划推进当前消息，完成本轮后等待下一条指令 日常对话与开发任务（默认）
Goal 由单个 Agent 围绕目标持续自主推进，直到完成或暂停，可设 Token 预算 长任务、需要自驱动的目标
Team 由主 Agent 动态组织多个 subagent 分工协同，可设团队 Token 预算 需要并行拆解的大块工作（需 Runtime 具备多 Agent 能力）

子代理模型：不同的活交给不同的模型

在「设置 › 模型 › 子代理」里给 fast、standard、strong 三个档位各选一个模型，选好即生效：主 Agent 派子代理时按任务挑档位——检索、整理用 fast， 一般的实现用 standard，设计、排错和审查用 strong。没设置的档位跟随当前会话模型。

需要固定说明、收窄工具或指定思考强度时，再写子代理定义。定义写了模型或档位时以定义为准， 优先级是：定义里的具体模型 → 定义里的档位 → 派发时挑的档位 → 当前会话模型。每个子代理一个 Markdown 文件： 

---
name: scout
description: 只读检索代码库，回答“在哪里、怎么用”的问题
model: fast            # fast / standard / strong，或 provider/modelId
thinking: low          # 可选：off、minimal、low、medium、high、xhigh
tools: [read, grep, find, ls]   # 可选：只能在当前会话已有的工具里收窄
---
只报告文件路径与行号，不改文件。
  • 项目定义放在项目的 .pisper/agents/ 下，可随仓库提交；全局定义放在数据目录的 agents/ 下，对所有项目生效。同名时项目定义覆盖全局定义。
  • fast、standard、strong 三个档位在「设置 › 模型 › 子代理」里映射到具体模型， 换供应商只改这一处，项目文件不用动。没设置的档位跟随当前会话模型。
  • 写具体模型时可以再加 tier: fast 作为退路：具体模型不可用就用档位模型，档位也没设置就用当前会话模型， 运行记录里会写明换成了哪个模型。
  • 审批模式和工作区范围始终跟随当前会话，定义不能放宽权限。
  • 不想手写也可以直接说“帮我定义一个只读检索的子代理”：Agent 会先读内置技能 pisper-subagents， 按上面的规则写好文件，并提醒你去设置里给用到的档位选模型。

辅助模型与备用模型

  • 辅助模型（「设置 › 模型」）：生成会话标题、压缩上下文、提取和整理记忆这类后台杂活改用它， 不再占用当前会话的主模型。首条消息发出后标题先按消息截取，辅助模型起好名字后再替换；手动改过的标题不会被覆盖。 不设置时一切照旧；设置的模型被删除、停用或写摘要失败时，自动退回原来的模型。
  • 备用模型：主模型重试后仍不可用或额度用尽时，按顺序切到备用模型，从中断处接着跑。

审批模式：决定权限边界

模式 可执行范围 适用场景
审批后写入 approval-required 修改工作区文件前展示 Diff 并等待批准；Shell 命令也需要逐条批准 代码审查、方案调研、需要确认的开发工作
自动审批 workspace-write 允许修改当前工作区并自动批准常规命令；访问工作区之外的文件需要确认 日常开发、重构、跑测试与构建
完全访问 full-access 允许访问本机文件和网络；Shell 不再逐次请求授权 需要完整主机权限的操作

三种模式下可用的工具完全一样（子代理也一样），模式只决定调用前要不要问你： 需审批时，联网搜索之外的中高风险工具（浏览器、MCP、插件等）每次确认；工作区写时，第三方插件工具仍逐次确认；两种模式下访问工作区之外的文件、创建全局技能也是确认后执行，不会直接拒绝；完全访问不再询问。

终端里用 /mode 查看与切换审批模式，如 /mode approval-required、/mode workspace-write、/mode full-access。

可视化工作流

把 Prompt、文件、MCP 与通知连成一张图，让重复的事交给流程跑。

  1. 新建工作流

    进入工作流页面，从空白图开始，或基于已有工作流复制。

  2. 连接节点

    拖拽添加 Prompt、文件输入、MCP 调用与通知节点，用连线定义执行顺序与数据流向。

  3. 试跑并观察

    手动运行一次，确认每个节点的输入输出符合预期后再接入定时任务。

定时任务与通知

定好频率与时区，到点 Agent 自己开工，结果推到你手边。

  • 触发目标：可以是一段 Prompt、已经调好的工作流，或者交给一个 Bot（需在设置 › 实验功能里打开 Bots）。
  • 通知渠道：系统通知之外，可接飞书与个人微信，实现双向对话。
  • 提示音：在 设置 › 通知 › 提示音 里，给“需要你”“做完了”“出错了”各挑一种音效（叮咚、木琴、水滴、铃声、低鸣，或不响），调音量；也可以只在你没看着 Pisper 时响。按设备保存。
  • 离开电脑也能跟进：渠道消息可直接回复，会话继续推进。

记忆

事实、偏好与决策会被记住，新对话里相关的内容自动带上，项目再长也不用重复自我介绍。

不需要确认

记忆直接生效，不用逐条审核。每次改动都写在整理记录里，附理由，看到不对的可以撤销。用户亲口说过的内容，不会被模型的推断顶掉；记忆只从你和助手的对话里提取，不读工具输出；外部渠道的消息不会自动进入对话。

分层

  • 原文：每轮对话脱敏后留一份，可以跨会话搜到“上次那个报错怎么解决的”。
  • 事实：一句话一条，带证据和时间，是唯一算数的一层。
  • 摘要：每个会话一份，再按天、周、月整理，回答“上次那个会话做了什么”“上周干了什么”。每次对话的摘要在记忆页的「会话」视图里，展开后能跳回原对话。
  • 画像：稳定的偏好和硬规则，会话开始时带上。

时间与自动淘汰

每条事实都记着何时为真、系统何时知道，既能查现在用什么，也能查当时用什么。

  • 被替换：同一件事有了新说法，旧版本转入历史，还能查到。
  • 引用失效：记忆提到的文件变了或没了，标记为“可能过期”。
  • 到期或长期不用：转入归档，可以恢复。
  • 你删除：连同历史版本彻底清除，之后也不会再被自动记回来。

时间演算

打开「功能 → 记忆」，拖动时间轴，或按播放，看记忆怎样一步步长成现在的样子：最外圈是那一刻最新的记忆，越靠里越早、也越暗；哪些在那一刻有效，哪些后来被替换、沉入归档。选中一条可以看证据和版本历史。旁边的「时间线」按日期列出全部记忆。

数据留在本机：记忆存在你自己电脑上的数据目录里，可以随时导出成 Markdown。

移动端 App

App 内置与桌面同源的 Node/Pisper Runtime，首次启动直接进入本机运行，不必先连电脑。

平台 安装说明
Android 已签名 arm64 APK，可直接安装；首次侧载按系统提示允许未知来源。
iOS 未签名 IPA，需用 AltStore、Sideloadly 或自有开发者账号重签。

本机运行

  1. 等待 Runtime 就绪

    首次启动会初始化内置 Runtime，随后直接进入正常 Pisper 界面。

  2. 配置 Provider

    会话、Provider 配置与工作区只保存在 App 私有目录。

  3. 了解能力边界

    本机 Runtime 仅监听随机回环端口，并会隐藏 embedded Node 无法承载的能力入口。

远程访问与配对

手机也可以连接桌面 Runtime，用电脑的算力和完整能力。配对必须由桌面端明确批准。

  1. 桌面端开启远程访问

    进入 设置 → 远程访问 开启。建议首次配对时手机与电脑在同一局域网。

  2. 手机发起申请

    在 设置 → 服务器 → 添加服务器 中允许本地网络访问，选择自动发现的桌面并发起申请。

  3. 桌面批准

    桌面用户明确批准后才会签发设备令牌。发现不到或异地时，改用桌面生成的一次性二维码。

链路安全：所有路径都校验 TLS 指纹并使用设备 Bearer 令牌；连接后优先走 LAN，不可达时回退 Iroh P2P。

远程机器

让 Agent 直接在别的机器上工作，对方不用安装 Pisper。模型和 API Key 留在这台电脑上，文件和命令工具在对方机器上运行，审批模式照常生效。在「远程访问」页添加机器，新建任务时在项目芯片里选择机器和目录。

  • SSH：对方要有 SSH 服务（OpenSSH、Dropbear、Tailscale SSH 都可以）和 POSIX shell。用这台电脑现有的 ~/.ssh/config、密钥和 ssh-agent 登录，Pisper 不保存密码和私钥，只支持密钥登录。
  • 让对方连过来：适合没有 SSH 服务的机器。对方需要 Node.js 20 以上，运行页面上给出的 npx pisper executor 命令配对，不开放端口。这台电脑要打开远程访问，并且对方能访问到它的地址。Agent 只能在配对时用 --root 指定的目录里工作。

远程会话里没有 MCP、插件、子代理和记忆，文件搜索由模型用命令完成。对方是 Windows 时暂不支持 SSH 方式。命令结束后留在后台的进程会继续运行；点停止会结束这条命令和它启动的进程。

数据与目录

Runtime 默认只监听 127.0.0.1，敏感格式会自动脱敏。

项目 位置
桌面 / 终端数据 ~/.pisper/agent，可用 PISPER_AGENT_DIR 覆盖
移动端数据 App 私有目录，随应用卸载一并清除

备份注意：该目录含 Provider 凭据与会话内容，请勿提交到仓库或公开分享。

组件更新

Desktop、TUI 与 Runtime 各自独立检查与更新，需要什么就只更新什么。

在 设置 → 更新 中查看各组件版本并单独触发更新；涉及 Runtime 替换的更新会提示重启。

常见问题

macOS 提示「无法打开」

Pisper 尚未经过 Apple 公证。确认安装包来自官方 Releases 后，在 系统设置 → 隐私与安全性 选择 仍要打开。若没有该选项： 

sudo xattr -rd com.apple.quarantine /Applications/Pisper.app

请仅对从官方 Releases 下载并放入 /Applications 的应用使用此命令。

Linux AppImage 无法启动

chmod +x Pisper_*_linux_x86_64.AppImage
./Pisper_*_linux_x86_64.AppImage

缺少 FUSE 时安装 libfuse2 或 libfuse2t64，也可改用 .deb。

提示有文件读不了

启动时发现读不了的数据文件（比如断电留下的半截文件），Pisper 会把它改名为 原文件名.corrupt-时间 留在数据目录 ~/.pisper/agent，用默认值继续启动，并在窗口右下角告诉你是哪些文件。原内容还在，能手动修好后改回原名。如果窗口显示「Pisper Runtime 无法启动」，请把下面那行错误发给我们。

模型请求失败

确认 Provider 可达、凭据有效、所选模型对你的账号可用。Provider 流量由你选定的 Runtime 直连，不经过第三方中转。

手机发现不到桌面

确认两端同一局域网、桌面已开启远程访问、手机已允许本地网络权限。仍失败就用二维码配对，截图也可发到异地手机。

还有其他问题

在 Issue 区 反馈，附上版本号、系统版本与完整报错。请勿粘贴 API Key、配对令牌或私有内容。
