# ChatGPT 网页与 Pisper 客户端布局对照

首次记录：2026-10-16；续验：2026-10-18。工作分支：`release`。本报告为进行中的验收记录，不代表已完成全部 1:1 对照。

## 参考与验证范围

- 实际操作已登录的 Safari ChatGPT 网页：工作/聊天首页、侧栏、探索菜单、个人菜单、设置常规页、外观页、明暗模式及附件入口；另外用不含个人信息的测试消息检查实际对话、回复操作菜单和编辑取消。
- 实际操作 Pisper Tauri 开发客户端，复用已有 Rust 可执行文件与当前前端构建；未重新编译 Rust、提交、推送或发布。
- 原生 ChatGPT 应用的访问限制仍然存在。网页中不存在的桌面专属场景，不能据此声称完成验证。
- Safari 原主题为跟随系统，浅色主题自定义强调色为 `#007ACC`。深色检查后恢复跟随系统；Pisper 深色检查后恢复原浅色偏好。参考账号的自定义主题不能当作所有用户的默认主题。
- 观察记录只包含布局与交互，不复制真实会话、配置凭据或文件内容。

## 客户端证据与剩余范围

已实际确认：开关展开后焦点落在侧栏开关；侧栏搜索结果可跳转到外观页；明暗切换有效；摘要打开后位于右上方；点击后台进程打开资源标签并聚焦；新建标签页展示工具入口；任务标题与资源标签栏同排；双任务窗口在重启后恢复且各自保留输入区；首页建议可逐组翻页、最后一组禁用下一页、可以返回第一页；顶部只常驻更多、摘要和新标签入口；更多菜单可打开追忆，关闭后焦点回到更多；菜单中的主题切换可遍历系统、深色、浅色并恢复原浅色偏好。

构建期间替换 `dist` 会使已运行客户端持有旧资源入口，引发模块加载失败；单纯页面重载不足，重启开发客户端与伴随进程后再验收。后续统一先构建，再启动客户端验收。分屏通过的依据是重启后实际观察到两个独立任务窗口和输入区。

网页测试会话已创建，仅包含界面对照测试文字，未上传文件或分享内容。实际聊天视图的用户消息为浅色强调色底、回复正文无外框，回复操作位于正文下方；该账号仍使用自定义浅色主题，因此颜色不能作为所有 ChatGPT 用户的默认值。编辑消息展开为文本框及取消/发送，取消后恢复原文。未删除该测试会话。

顶部按钮的尺寸检查需要等断点过渡完成后再读取：曾采到中间帧导致误报。现在等待实际 Web Animations 完成，再在一次同步读取中检查整组边界；未放宽 44px 标准或增加固定等待。

深色网页测试对话已实际观察：用户消息使用低亮度蓝色底与浅色文字，输入框比主画布稍亮。Pisper 已按中性主题规则改为深灰气泡与浅色文字，输入框使用略亮的深灰表面；浅色气泡改为浅灰与黑字。已在重新启动后的 Tauri 客户端实际检查两种主题，恢复原浅色偏好。网页保留原“系统”模式。

消息配色批次的构建、37 项相关测试、格式检查及工作区回归均通过。新增主题契约先验证旧配色失败，再验证文字对比度至少 4.5:1、气泡与画布不形成反色高对比表面。工作区回归仍覆盖分屏、草稿、阅读位置与移动端返回。

Safari 的“进入响应式设计模式”在当前窗口显示为禁用。续验通过拖动窗口边缘实际缩窄到约 574 CSS px，观察到：功能栏收进侧栏抽屉、正文左右留白缩小、输入框转为上下两行，抽屉使用白色侧栏与浅色遮罩，点击遮罩后关闭。已恢复原窗口宽度。该证据属于窄窗口响应布局，不能代替 320/390px、触摸键盘或 iOS Safari 真机验证；没有更改浏览器开发或安全设置。Pisper 常驻功能栏继续遵循用户明确要求，作为与参考网页的有意差异保留。

回复操作批次：`npm run check`、构建、43 项相关测试、`test:workbench` 和主应用 UI 冒烟（`node scripts/smoke-pisper-ui.mjs`）通过。主应用 UI 报告目录为 `pisper-ui-nEChH2`，工作区报告目录为 `pisper-workbench-V9lCXd`；本批未重复运行未受影响的工作流和移动壳专项。交互用例先观察到缺少复制按钮而失败，再覆盖复制原始 Markdown、拒绝后失败反馈与重试、手机 44px 点击区域、两个分支回调、重试回调、流式期间收起操作栏及关闭菜单后的焦点恢复。原先固定四个 Tooltip 的源码守卫已迁移为菜单文字与交互可达性验证；标签和 Runtime 调用守卫仍保留。客户端实际复制显示“已复制”，更多菜单显示两种分支操作，Escape 后焦点回到原按钮，未对真实会话执行分支或重试。

外观与抽屉批次：`npm run check`、构建、`test:workbench` 和主应用 UI 冒烟通过（工作区报告 `pisper-workbench-kinVPm`，主应用报告 `pisper-ui-oxxNsL`）。新增用例先验证旧单选组存在四个 Tab 入口，再覆盖六组选项的单一 Tab 入口、方向键切换、焦点跟随、强调色菜单、自定义 HEX 错误状态、320px 无横向溢出、抽屉打开焦点、Escape 关闭恢复焦点、574px 抽屉宽度及点击遮罩关闭。测试曾发现真实的关闭后焦点丢失，修复后通过。

方向键验证使用按下、等待选择完成、抬起的完整事件序列；Radix 的焦点移动发生在下一事件循环，未通过固定等待或放宽断言规避失败。客户端实际确认右方向键从浅色切到深色，左方向键恢复浅色，选中态与焦点同步。最终客户端检查确认强调色控件位于设置行右侧，字体和圆角选项高度一致；保留原浅色与中性黑偏好。桌面窗口缩窄受到应用最小宽度约束，不能将它记为手机 WebView 验证。

用户消息复制批次：先观察到缺少复制按钮的用例失败，再验证复制原始 Markdown、窄屏 44px 点击区域、桌面悬停显隐和 Tab 键可达性通过。客户端重启后点击用户消息的复制入口，实际出现“已复制”反馈。该批 `npm run check`、构建、工作区回归通过；全量测试为 2726 项、2724 通过、2 跳过、0 失败。此结果早于随后追加的排版调整，不作为排版最终验证的替代。

正文对照：在同一个网页测试会话追加不含个人信息的整理桌面排版请求。Safari 初次未绘出回复正文，重新载入并等待页面恢复后实际看到标题、两段正文与三条列表；又以约 574 CSS px 的窄窗口检查换行和两行输入区，最后恢复窗口尺寸。根据截图比例制定 Pisper 的 16px / 26px 排版目标，属于视觉对照后的设计值，未宣称读取了 ChatGPT 的 CSS。自动化先验证旧实现为 15px 而失败。
