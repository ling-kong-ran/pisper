# Pisper 前端工作台设计方案

- 日期：2026-10-14
- 状态：整体布局、样式治理方向和页面模板已确认，本文为供评审的完整设计规格；尚未进入产品实现。
- 设计基线：本会话第四版交互预览 `pisper-task-workspaces-v4.html`。
- 适用范围：React Web、桌面 WebView、Android 和 iOS 的前端界面。
- 本轮交付：设计文档。生产源码、接口、运行时、原生工程和发布流程不作修改。

Pisper 采用三层布局：始终可见的功能栏、可以隐藏的项目与会话侧栏，以及承载任务的主工作区。任务拥有自己的工作上下文，标签页展示任务相关内容，分屏负责同时展示多个任务。

日常使用从选择项目和任务开始。对话与输入框构成默认工作界面；文件、变更、终端、进程和来源通过摘要或新标签入口打开。复杂能力按需展开，用户无需先组织多个面板才能开始工作。

## 1 目标与边界

### 1.1 设计目标

1. 项目、任务、内容标签和分屏具有不同职责，避免同一批任务同时出现在多套顶层标签导航中。
2. 切换任务时可以继续先前的阅读与输入，不需要重新打开相关内容。
3. 并行工作时始终能判断当前焦点、操作对象和资源所属项目。
4. 默认界面留白充足；展开工具后仍保留对话的连续性。
5. 桌面、平板和手机共享任务与资源语义，通过显示方式适配可用空间。

### 1.2 本方案不扩大的范围

本方案不引入新的代理引擎、编辑器内核、后端业务协议、项目隔离机制或终端进程管理语义。文件是否可编辑、是否支持来源管理、进程是否可停止，均服从已有能力和权限。

布局调整不删除已有工作流、计划任务、技能、MCP、插件、计划面板或侧聊入口。已有能力归入新的导航层级；未实现能力不能因为预览中有演示入口而被宣称支持。

原型中的任务、文件差异、命令、来源和运行状态是演示数据。原型刷新后重置；这不是正式产品的持久化规则。

## 2 核心对象与关系

| 对象       | 定义                                   | 拥有的内容                                           |
| ---------- | -------------------------------------- | ---------------------------------------------------- |
| 项目       | 由现有项目或工作目录模型确定的业务范围 | 项目显示名称、工作目录、文件与版本控制上下文         |
| 任务       | 用户选择并持续推进的一项会话工作       | 对话、草稿、内容标签、任务摘要与任务相关活动         |
| 任务工作区 | 某个任务在界面中的完整工作上下文       | 当前标签、阅读位置、文件展开状态、筛选和面板显示状态 |
| 内容标签   | 某种资源或工具的视图                   | 变更、文件、终端、网页、后台进程、来源等             |
| 分屏       | 放置任务工作区的显示容器               | 绑定的任务、尺寸、位置和焦点关系                     |
| 功能栏     | 全局功能的导航入口                     | 工作台、项目、资源、自动化、扩展、设置               |

任务的身份使用现有会话标识，不使用标题、显示顺序或临时端口。若同时展示不同连接中的任务，身份还须包含已有的连接作用域，不能让相同标识跨连接串用状态。

一个任务在当前工作台中至多显示在一个分屏内。再次打开已经可见的任务，直接聚焦原分屏，不复制对话、输入草稿或内容标签。

任务拥有资源的“视图状态”，不意味着它独占资源本身。多个任务使用同一目录时，可以看到同一份项目变更；同一终端的连接和目录不会因为界面焦点变化而改变。

## 3 三层布局

### 3.1 第一层 始终可见的功能栏

功能栏位于最左侧，在桌面、平板和手机上都不随侧栏折叠、任务切换或内容标签打开而隐藏。手机模态抽屉打开时可以覆盖半透明遮罩并暂时禁止背景操作，但功能栏仍保留视觉轮廓。

功能栏只承担应用级导航。项目列表、任务列表及具体文件列表不放入这一层。

| 分组   | 一级入口 | 展开后的内容与作用域                                         |
| ------ | -------- | ------------------------------------------------------------ |
| 工作台 | 工作台   | 回到任务工作区，保留任务与布局状态                           |
| 工作台 | 项目     | 展开项目与会话侧栏，不切换当前任务                           |
| 工作   | 资源     | 当前任务的项目变更、项目文件、终端、后台进程、来源、网页预览 |
| 工作   | 自动化   | 工作流、计划任务                                             |
| 扩展   | 扩展     | 技能、MCP 服务、插件与工具                                   |
| 底部   | 设置     | 外观与布局、模型与服务、快捷键，以及既有设置入口             |

资源菜单标题或说明显示“打开到当前任务”，避免与跨项目的资源库混淆。已有全局资源库仍是独立页面入口，不自动被重解释为当前项目文件。

图标提供可访问名称、悬停说明和键盘焦点样式。低频功能通过分组菜单展示，不把每一种工具都变成常驻图标。已知不可用的能力不显示可执行入口；恢复旧标签时遇到能力不可用，则在原标签内解释原因。

### 3.2 第二层 项目与会话侧栏

侧栏按项目组织任务，当前任务有明确选中状态。任务行同时展示名称和简短状态；运行、待处理、失败等不能仅靠颜色区分。

- 项目内展示该项目的任务。
- 无项目任务归入“其他会话”，不重复列出已在项目分组中的任务。
- 置顶、归档和搜索遵循已有会话组织语义；折叠项目不会关闭任务。
- 点击任务名称选择或聚焦任务；任务行的分屏操作是独立按钮，不与普通选择混用。
- 搜索保留项目归属，支持无匹配结果的空状态。
- 新建会话属于当前项目；没有当前项目时走现有项目选择或无项目会话流程。

侧栏开关放在窗口顶部靠左、品牌附近，独立于功能栏和任务内容。它始终可达，名称随状态变为“显示项目与会话侧栏”或“隐藏项目与会话侧栏”。

桌面侧栏展开时占用布局宽度，隐藏后释放给主工作区。手机侧栏在功能栏右侧覆盖内容区，选择任务后收起；这不改变桌面的展开偏好。

### 3.3 第三层 主工作区

主工作区容纳一个或多个任务工作区。没有打开任务时，显示项目选择、新建任务和最近工作入口；不预先铺开空终端、空审阅或空摘要。

单任务默认显示对话和输入框。阅读区限制最大宽度并与输入框对齐；窗口变宽后增加两侧留白，而不是无限拉长正文行。

主内容面使用稳定的背景与边界。日常消息以排版组织层级，文件或工具结果使用少量可操作卡片。

## 4 任务工作区顶部与主体

### 4.1 顶部操作区

每个分屏都有独立的任务标题区。标题明确显示当前任务名称，辅助行显示项目名称与任务状态；长标题截断时必须可查看完整名称。

标题区包含以下操作，顺序保持稳定：

1. 项目与当前任务的更多设置。
2. 切换置顶摘要。
3. 新建内容标签页。
4. 分屏操作。

“更多设置”内部区分项目级与任务级操作。修改项目显示名称不能改变目录绑定；归档任务、关闭分屏、收起内容区不能被混为同一动作。删除等现有业务操作继续遵循原有确认机制，不因移动入口而弱化。

当前焦点分屏在标题区使用细标记或轻量强调。失焦分屏仍可阅读，但资源菜单、任务选择和依赖焦点的快捷操作以当前焦点分屏为目标。

### 4.2 主体结构

宽度充足时，对话位于左侧，内容标签的面板位于右侧；内容标签栏与任务标题处于同一顶部层级。

宽度不足时，对话与内容标签交替显示。内容标签区域提供“返回对话”，只收起内容视图，不删除标签。再次进入内容区时恢复原选中标签。

输入框属于任务对话，只在该任务的对话视图中出现。切换到窄屏内容视图时，草稿仍由任务持有。对话滚动和输入框布局分离，长消息不能将输入框挤出可视区域。

## 5 置顶摘要

### 5.1 桌面浮窗

摘要在当前任务工作区右上方以浮窗打开，不再作为横向摘要条常驻正文上方，也不创建新的原生窗口。

浮窗顶部显示项目和任务归属，下方按顺序展示：

| 区块     | 概览内容                       | 点击行为                                     |
| -------- | ------------------------------ | -------------------------------------------- |
| 项目变更 | 文件数量、增加与删除行数       | 打开或聚焦项目变更标签                       |
| 后台进程 | 少量进程名称、文字状态、总数   | 打开进程标签；点击具体进程时定位其日志或详情 |
| 来源     | 少量来源名称、类型、归属、总数 | 打开来源标签；点击具体来源时定位该条目       |

区块提供“查看全部”，内容较多时浮窗内部滚动。摘要不展示完整 Diff、完整日志或长篇来源正文。

同一时刻只显示当前焦点任务的摘要。焦点切到另一任务后，摘要内容按该任务自己的显示状态决定，不保留错归属的旧内容。分屏时浮窗锚定所属任务工作区，不能覆盖另一任务后仍表现为其摘要。

宽屏且正文有足够空间时，为浮窗留出安全阅读空间；较窄桌面工作区允许短时覆盖当前任务内容，但不能超出工作区边界或遮住关闭入口。浮窗不建立一个可拖动的永久第四栏。

点击摘要开关、关闭按钮或按 Escape 可关闭浮窗。普通的背景点击不自动关闭桌面置顶摘要。点击摘要中的资源项后关闭摘要并打开对应标签，避免摘要继续盖住详情。

### 5.2 移动端底部抽屉

手机摘要从底部打开，宽度限制在功能栏右侧的主内容范围内。抽屉遵循安全区域，限制最大高度，长列表在抽屉内部滚动。

抽屉打开时：

- 焦点进入抽屉，背景区域不可交互。
- 功能栏仍可见，但不接受操作，避免背景任务被误切换。
- 可以通过关闭按钮、遮罩、Escape 或系统返回关闭。
- 关闭后焦点回到摘要开关；从条目进入内容标签时，焦点进入该内容视图。
- 抽屉不能使对话草稿或阅读位置丢失。

抽屉的拖动关闭可以作为触屏增强，不能是唯一关闭方式。

### 5.3 摘要状态

摘要开关属于任务当前界面的临时状态。同一页面生命周期内切换任务可以记住；刷新或重启后默认关闭，不将弹层状态写入通用页面偏好。

内容加载失败时区块显示局部错误与重试，不把失败解释为“0 个变更”或“没有进程”。缺少能力与真实空数据使用不同状态。

## 6 内容标签页

### 6.1 新建入口

顶部“＋”创建当前任务的新内容标签，显示工具入口与网页地址输入区域。它不创建新任务，也不切换项目。

入口按能力提供项目变更、文件、终端、后台进程、来源和网页预览。现有计划与侧聊能力继续保留适当入口；不因原型未展示而移除。

从新标签入口选择工具时，优先把当前空白标签转换为目标内容。若已有可复用标签，则聚焦已有标签并移除未使用的空白入口，避免留下重复空白页。

网页输入继续使用现有 URL 校验、平台桥接和安全引用机制。独立原型不访问外部网址；正式界面不能把原型的静态页面当作真实导航结果。

### 6.2 标签类型与复用

| 类型     | 资源范围               | 默认复用规则                                         |
| -------- | ---------------------- | ---------------------------------------------------- |
| 项目变更 | 当前项目或工作树       | 同任务同项目同一比较范围复用；不同范围明确命名       |
| 文件     | 项目文件资源           | 同一连接、项目和规范化路径定位已有内容               |
| 后台进程 | 当前任务关联的进程集合 | 同任务复用列表；进入时可定位具体进程                 |
| 来源     | 当前任务引用的材料     | 同任务复用列表；进入时可定位具体来源                 |
| 终端     | 明确的终端实例         | 新建动作创建新实例；打开已有实例按实例标识复用       |
| 网页预览 | 当前任务的网页视图     | 新标签可以独立存在；重复打开明确指定的已有预览则定位 |
| 计划     | 当前任务计划           | 沿用现有单一计划视图与能力约束                       |
| 侧聊     | 当前主任务关联的侧聊   | 沿用同一主任务复用侧聊的现有规则                     |

标签标题显示内容身份，而不是再次把所有任务名称列为标签。必要时在标题、辅助信息或面板底部展示项目、任务、文件路径和目录绑定。

### 6.3 选择与关闭

- 选择标签只切换当前任务的内容视图。
- 关闭活动标签后优先选择其右侧标签，右侧不存在时选择左侧标签。
- 关闭最后一个内容标签后回到对话，不自动新建一个可见的空文件标签。
- 收起内容区保留标签集合；关闭标签仅移除视图。
- 标签数量超限必须明确提示，不能无响应或静默丢弃旧标签。实现初期沿用当前内容页上限 12 的兼容基线；调整上限应另行说明依据。
- 标签溢出时局部滚动，并提供完整名称和切换方式，不推动整个工作区横向溢出。
- 如已有内容编辑能力存在未保存修改，关闭行为沿用该能力的保护流程；本方案不新建通用编辑器。

任务间不支持通过拖动直接改变资源归属。需要跨任务引用时，使用明确的打开或引用动作，重新验证连接、项目和权限。

### 6.4 标签与资源生命周期

关闭终端标签、后台进程标签、内容区或任务分屏，不等于停止实际进程。停止或取消必须通过已有的明确动作执行。

终端连接在创建时绑定项目目录、连接和实例标识，不能随任务焦点重新解释。网页、文件和日志也必须通过稳定资源标识恢复，不能仅按显示标题查找。

如果进程已经退出、资源被删除或连接失效，保留可识别的标签并显示对应状态。不得在用户不知情时创建新终端来冒充恢复成功。

## 7 任务切换与多任务分屏

### 7.1 普通任务选择

| 场景                       | 行为                                             |
| -------------------------- | ------------------------------------------------ |
| 只有一个分屏，选择其他任务 | 在该分屏恢复所选任务的工作区                     |
| 多个分屏，所选任务尚未显示 | 只替换当前焦点分屏                               |
| 所选任务已经在某个分屏显示 | 聚焦已有分屏，不复制任务                         |
| 从资源菜单打开内容         | 打开到当前焦点任务                               |
| 从某条任务结果卡片打开内容 | 由卡片所属任务决定归属，不受另一个分屏的焦点干扰 |

任务切换不取消运行、清空草稿或关闭其他任务资源。异步请求返回时必须校验任务和资源身份，不能把旧任务结果写入新任务面板。

### 7.2 分屏创建与调整

任务行提供“在右侧打开”，顶部提供分屏操作。用户显式执行分屏动作时，建立新的显示位置；普通点击任务行不会隐式增加分屏。

继续复用现有 Dockview 的分屏与布局能力。上下左右的既有打开语义需要保留可达入口，不通过新界面无意缩减。

第四版原型只演示两个工作区，不将“两栏”定义为正式产品硬上限。新增分屏受到实际可用空间约束；放不下时说明原因，保留原有任务和布局，不静默替换另一个任务。原型中两栏已满后替换焦点分屏的简化行为不进入正式规则。

调整分隔条只改变显示尺寸。分隔条支持指针和键盘操作，并提供恢复默认比例的方式。窗口临时变窄时可以限制显示尺寸，但不能把临时约束覆盖成用户长期偏好。

### 7.3 分屏焦点与关闭

点击分屏内部，或通过键盘进入其中的控件，即可使它获得焦点。获得焦点不改变其他分屏的任务、标签选择或草稿。

关闭分屏只移除显示容器，任务与任务工作区状态仍保留。再次从侧栏打开该任务时恢复其上下文。关闭后焦点移动到相邻可见分屏；最后一个分屏保持工作台的正常空状态或当前任务入口。

关闭、隐藏或卸载某个视图不得通过意外副作用停止任务、终端或共享订阅。

### 7.4 窄分屏

每个分屏根据自己的宽度决定能否同时显示对话和内容区，不只根据整个窗口判断。较窄分屏采用单内容切换：打开文件或日志时显示内容视图，“返回对话”恢复输入区。

另一个分屏继续保留原显示状态。不能为了打开当前任务的一个文件而重排、隐藏或替换另一任务。

## 8 项目变更

变更列表每个文件占一行。行内包括展开标记、文件标识、可辨识文件名、必要的路径、修改状态与增删行数。

文件名优先可读；长路径可以弱化或截断，但展开内容中必须提供完整路径。新增、修改、删除和重命名分别使用文字或图形标识，不能仅使用颜色。

- 首次打开默认收起全部文件；点击文件行展开该文件的差异，再次点击收起。
- 多个文件可以同时展开，不采用只能打开一个条目的互斥手风琴。
- 提供“全部展开”和“全部收起”。大文件内容按需加载，不在切换展开状态时阻塞整个列表。
- 展开状态、比较范围和阅读位置属于该任务的变更标签，在任务切换后恢复。
- 项目目录变更共享同一数据源；不同任务的展开状态可以不同。

需要明确比较范围，例如工作目录变更、暂存变更或分支比较。已有能力没有支持的比较范围不能仅在前端伪造选择器。

没有变更时显示正常空状态；加载失败显示错误与重试。二进制、图片、超大文件和不可读取文件提供对应预览或说明，不显示空白代码块冒充文本 Diff。

刷新变更数据不跳到列表顶部、不抢走当前文件焦点。若正在查看的文件消失，显示其状态变化并允许返回列表。

## 9 后台进程

进程列表以名称为主要信息，辅以状态、命令、目录和任务归属。命令与路径使用等宽字体，状态使用图形和文字的组合。

运行中、等待处理、已完成、失败、已停止和连接中断应按照实际数据映射，不根据日志中的临时文案猜测。未知状态提供中性说明，不归为成功。

列表提供全部与有意义的状态筛选。空筛选与没有任何进程使用不同文案。

点击“查看日志”在对应进程行下展开日志，保持名称、状态与日志的视觉联系。日志支持独立滚动和暂停自动跟随；用户向上阅读时新输出不能强制拉回底部。

停止、重试、清理记录等操作只在现有接口与权限支持时显示。预览只演示日志查看，不作为这些写操作已经具备的证据。

任务关联必须有实际数据依据。只能获得项目级进程时，应标注“项目进程”，不能把整个项目的进程都称为当前任务启动。

日志展示复用已有截断、结构化错误和脱敏机制；本设计不改变日志采集规则，也不扩大发送日志的范围。

## 10 来源

来源以紧凑列表展示，每项包含类型标识或缩略图、名称、格式、来源方式，以及必要的任务归属。

支持搜索名称与按类型筛选。类型按真实材料区分，例如图片、文档、链接和记录；数据不存在的类型不伪造数量。

点击来源在列表中展开简要详情，显示材料身份、来源方式和关联关系。需要完整预览时打开相应内容标签，不把大图或长文直接展开进摘要浮窗。

“添加来源”正式接入时复用已有附件、文件选择和引用能力，用户内容仍由原所属服务持有。原型中的“添加示例”只用于查看样式，不能原样成为产品操作。

移除任务引用不等于删除原始文件，两者必须使用不同操作语义。当前没有移除引用能力时不提供看似可执行的删除按钮。

材料失效、文件不可访问、解析失败、无匹配搜索结果分别显示对应状态。缩略图缺失时使用类型占位，不阻塞列表。

## 11 手机与平板

### 11.1 显示方式

三层职责在移动端保持不变，但不要求三层同时完整展开。

| 区域           | 手机规则                                               |
| -------------- | ------------------------------------------------------ |
| 功能栏         | 始终可见，使用紧凑图标，保持足够触摸区域               |
| 项目与会话侧栏 | 从顶部开关打开，在功能栏右侧覆盖主内容；选择任务后收起 |
| 对话           | 默认主要界面，正文可滚动，输入框保持可达               |
| 内容标签       | 单面显示，通过顶部返回操作回到对话；保留标签集合       |
| 摘要           | 底部模态抽屉，背景暂不可操作                           |
| 多任务分屏     | 保留各分屏绑定，以任务切换条一次显示一个工作区         |

平板根据可用宽度恢复并排显示。当前移动壳的 phone/pad 判断以实际实现为兼容基线，不仅用操作系统名称决定布局。

### 11.2 返回与关闭优先级

用户执行返回或 Escape 时，优先处理最上层的可关闭状态：

1. 关闭当前菜单、对话框或摘要抽屉。
2. 收起覆盖式项目侧栏。
3. 从内容视图返回所属任务的对话。
4. 上述状态都不存在时，交由已有路由或平台返回规则处理。

单次返回只关闭一层。不能同时关闭抽屉、清空标签并离开任务。桌面网页的浏览器历史操作继续遵守既有路由，不随意拦截系统快捷键。

### 11.3 触屏与键盘

不依赖悬停才能找到主要动作。任务分屏、标签关闭和浮窗关闭在触屏上都具有可见入口或明确菜单入口。

虚拟键盘出现时使用现有视口与安全区域适配；输入框不能被键盘盖住，也不能把任务标题或关闭入口推到不可达位置。关闭键盘不重建会话、不清空草稿。

横向手势保留给已有明确的导航场景。代码块、终端、标签栏、表单输入、滑块和弹层内部的手势由对应控件优先处理，避免滚动时误切换任务。

从手机变为宽屏时恢复原有分屏绑定与布局意图，不能把手机只显示一个工作区误写为用户主动关闭其他分屏。

## 12 状态归属与恢复

### 12.1 状态所有者

| 状态                       | 所有者                         | 不应由谁拥有                   |
| -------------------------- | ------------------------------ | ------------------------------ |
| 当前项目与全局导航         | 应用壳及现有项目导航层         | 基础按钮、菜单等 UI 原语       |
| 任务目录与运行数据         | 聊天领域的既有查询与会话同步层 | 每个分屏重复创建的权威副本     |
| 草稿、标签集合、阅读位置   | 任务工作区状态                 | 分屏容器或全局唯一标签集合     |
| 分屏位置、比例与焦点       | 工作台布局状态                 | 单个内容标签                   |
| 文件、变更、进程、来源实体 | 对应领域数据源与 API 层        | 展示组件内自行请求并复制的数据 |
| 终端连接与运行生命周期     | 现有终端服务与连接所有者       | 终端标签的挂载和卸载钩子       |
| 弹层开关、悬停和焦点回退   | 当前交互视图                   | 通用持久化配置                 |

### 12.2 恢复范围

| 内容                           | 同一次页面生命周期内切换任务 | 刷新或重启                                               |
| ------------------------------ | ---------------------------- | -------------------------------------------------------- |
| 主题、桌面侧栏开关与宽度       | 保留                         | 通过现有页面偏好机制恢复                                 |
| 合法的分屏结构与活动任务身份   | 保留                         | 沿用现有布局持久化；结构不合法时安全回退                 |
| 内容标签集合与活动标签         | 按任务恢复                   | 本期不把资源地址、用户内容写入通用偏好；不承诺完整恢复   |
| 输入草稿与侧聊临时内容         | 按任务保留                   | 仅遵循已有草稿能力，不新增跨重启持久化承诺               |
| 文件展开、筛选、搜索和阅读位置 | 按任务或标签保留             | 作为临时视图状态重置，除非已有明确的领域持久化支持       |
| 摘要、菜单与移动侧栏临时开关   | 按交互规则保留或关闭         | 默认关闭                                                 |
| 实际进程和终端状态             | 由资源服务维持               | 重新查询或按已有连接协议恢复，不用旧 UI 快照伪造运行状态 |

需要跨应用重启保存的偏好统一经过实际路径 `src/lib/storage/page-state-storage.ts` 中的 `pageStateStorage`，并登记到 `shared/browser-preferences.mjs`。不得新增只写 `localStorage` 的持久化偏好。

临时网页 URL、凭据、对话内容、终端缓冲区和来源正文不得写入通用页面偏好。界面状态与领域数据分开恢复。

不活跃任务可以释放昂贵的渲染实例，但应保留本次页面生命周期内承诺恢复的轻量视图状态。不能通过回收面板静默丢弃未发送草稿。存量上下文状态缓存的回收策略需要随实现一起检查。

## 13 视觉规范

### 13.1 表面与颜色

浅色使用轻灰应用壳、浅灰导航和白色主内容面；深色按相同层级映射。边框负责区域分隔，阴影主要用于浮窗、菜单和输入区，不给每条消息增加卡片阴影。

主操作保持中性对比，交互强调默认使用蓝色，也可使用经过对比度校验的用户强调色。成功、等待、失败等使用独立语义颜色并同时展示状态文字，不跟随用户强调色改变。

复用现有 Tailwind、shadcn 与语义主题令牌。不将原型的固定色值直接散布进产品组件，不向全局 CSS 添加页面或控件语义类。

### 13.2 候选尺寸

以下是初始设计参数，不是对参考截图的精确测量，也不是新的平台支持或性能限制。

| 项目           | 初始设计参数                                       |
| -------------- | -------------------------------------------------- |
| 功能栏         | 桌面约 52px，手机约 44px；手机点击区域约 44px      |
| 项目侧栏       | 默认约 248px，可调范围优先兼容现有宽度偏好         |
| 单任务阅读区   | 最大宽度约 780px，随分屏与摘要空间收缩             |
| 正文           | 约 15px，舒适行距；服从用户既有字体设置            |
| 常规界面       | 约 13–14px；次要说明适度降低字号与对比             |
| 圆角           | 控件约 6–8px，主内容面约 14–16px，输入区约 18–22px |
| 桌面摘要       | 默认约 320px，限制在所属工作区范围内               |
| 手机摘要       | 最大高度约为当前可用内容区的四分之三，内部滚动     |
| 对话与内容并排 | 参考工作区可用宽度 660px；不足时切换为单内容视图   |

并排阈值作用于每个任务工作区，不作用于整个浏览器宽度。中文、英文、字体缩放和系统安全区域都进入验证；空间不足时优先收起次要区域，不缩小到不可读字号。

动效只用于表达展开、收起和焦点关系，尊重减少动态效果设置。切换主题或调整宽度不重新触发网络任务。

### 13.3 Tailwind 与独立 CSS 的使用规范

样式按设计令牌、基础控件、应用组合、领域界面四层组织。Tailwind 用于消费设计令牌并组合布局；独立 CSS 保留必要的主题、基础规则、关键帧和第三方适配。

| 层级           | 职责                                               | 实现边界                                             |
| -------------- | -------------------------------------------------- | ---------------------------------------------------- |
| 设计令牌       | 色彩、字号、圆角、阴影、主题与公共尺度             | CSS 变量作为单一来源，通过 `@theme` 映射为语义工具类 |
| 基础控件       | 按钮、输入、标签、弹窗、抽屉和分隔条               | 优先既有 shadcn 组件，差异用明确的类型化变体表达     |
| 应用组合与布局 | 页容器、页头、工具栏、分节标题、状态视图和列表详情 | React 组件组合 Tailwind；只接收参数、回调与插槽      |
| 领域界面       | 业务内容、页面编排和交互                           | 消费公共组合；模型、请求和状态仍归所属 Feature       |

**常规布局与控件规则：**

1. 优先使用已登记的语义颜色和间距、字号、圆角尺度；特殊尺寸有实际原因时可以使用任意值，不把任意值全部视为错误。
2. 重复的工具类组合提取为职责明确的组件或类型化变体。禁止通过新增全局语义类或 `@apply` 别名掩盖重复业务样式。
3. 共享组件不得通过 `.memory-layout`、`.skill-scope-head` 等 Feature 父级类名决定自身外观。页面布局由页面控制，组件变化由参数表达。
4. 新代码不继续引用已退役的 `--r-*`、`--sh-*` 等旧别名。存量调用方分批迁移，不能为删除别名进行无关改写。
5. 工具类必须能由实际 Tailwind 入口生成。普通 `--surface-subtle` 变量并不自动生成 `bg-surface-subtle`；需要相应主题映射或改用已有有效工具类。
6. 动态变体使用可以静态发现的完整类名映射，避免拼接不可扫描的颜色或尺寸类名。动态坐标、拖拽尺寸、图形位置可通过内联样式或 CSS 自定义属性传递。
7. 普通控件的样式冲突通过组件契约解决，不层层追加 `!important`。必须使用重要性规则的兼容或第三方适配需要限定范围并说明原因。
8. 类名顺序统一交给现有格式工具；不能把排序、压缩类名或缩短文件视为职责治理。

**允许保留的独立 CSS：**

- 设计令牌、浅深主题、必要的基础元素规则和 Tailwind 映射。
- 关键帧、复杂选择器及无法清晰表达为工具类的效果。
- Dockview、xterm、Markdown／Streamdown 等第三方生成内容的有范围适配。
- 已有 Safari 与旧 WebView 兼容降级，包含颜色透明度等必要保护。

页面布局、普通控件外观和业务卡片不得继续扩张到全局 CSS。是否拆分样式文件取决于职责和加载边界；拆分时保留导入顺序及兼容行为。

字号使用界面正文、辅助说明、标题、对话阅读和代码等明确角色。治理全局 `small !important` 时，先迁移其调用方并验证用户字号设置；不能直接删除规则后让存量页面出现不可控变化。

### 13.4 强调色与主题规则

采用“中性主操作、有限交互强调、独立状态色”。默认 neutral 的方向保持，用户强调色只影响明确列出的交互角色。

| 色彩角色                      | 规则                             | 用户强调色的作用                   |
| ----------------------------- | -------------------------------- | ---------------------------------- |
| 页面、导航、卡片与浮层        | 按浅深主题呈现中性表面层级       | 不改变                             |
| 主操作 `primary`              | 浅色墨色、深色反白，前景保持清晰 | 不整体改成用户色                   |
| hover 与普通选中底色 `accent` | 轻量中性表面，遵守组件系统语义   | 不直接映射成品牌色                 |
| 活动指示、部分交互链接        | 少量、明确、可辨识的强调         | 使用经过校验的派生色               |
| 键盘焦点 `ring`               | 在实际相邻表面上可见             | 可以派生，不能直接使用任意原始 HEX |
| 信息、成功、警告、危险        | 使用各自稳定语义和文字标识       | 不改变                             |
| 代码、Diff、图表与资源类型    | 使用内容所需的配色               | 不随界面强调色统一替换             |

交互选中态仍需通过字重、边界、标记或图标等辅助表达；不能只靠颜色辨别。危险操作继续使用独立 destructive 语义，不受中性主操作规则限制。

新组件按用途选择颜色，不再根据 `blue`、`star` 等历史名称推断角色。迁移期允许旧名称映射到新语义，但该映射只能作为兼容层，不继续增加新的消费者。

颜色验证以实际前景、背景与状态组合为单位：普通大小文字以至少 4.5:1 为基准，用于识别控件或状态的必要非文本标记参考 3:1；装饰性边界与禁用控件按相应适用条件评估，不机械套用同一门槛。焦点环必须单独检查，自定义按钮文字可读不能替代焦点可见性验证。[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

矩阵包含浅色与深色、各预设、自定义极亮和极暗颜色，以及默认、悬停、按下、焦点、选中、禁用和错误状态。复用现有对比度派生能力，补齐预设前景和焦点规则；不能只依赖颜色看起来协调。

已有预设和自定义颜色值需要保留，并迁移到受约束的交互角色。收窄强调范围时，同步修改设置文案，说明颜色影响的位置；不得静默重置为默认色或删除用户选择。仅必要的偏好格式变化才增加版本或迁移，不为样式调整复制新的偏好存储。

### 13.5 四类页面模板

页面采用以下四类模板。同一 Feature 可以包含不同模板，例如工作流列表与工作流编辑器；模板按使用方式划分，不按目录名称硬套。

| 模板     | 适用页面                                            | 结构与宽度                                                          | 滚动与窄屏规则                                                       |
| -------- | --------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 工作台   | 聊天任务、工作流编辑器、画布界面                    | 占满剩余区域，顶部工具与主体分离；任务工作区遵循本方案第 4 至 11 节 | 各面板有明确滚动所有者；按局部宽度收起检查器或切换单内容视图         |
| 列表详情 | 计划任务、渠道、MCP、技能管理、记忆管理中的列表视图 | 左列表右详情，确有独立信息职责时允许检查器                          | 列表与详情分别滚动；窄屏在列表与详情之间切换，返回保留列表位置与选择 |
| 集合页   | 资源库、插件市场、工作流列表                        | 统一页头和过滤工具栏，主体使用列表或自适应卡片网格                  | 主内容容器滚动，网格列数依可用空间调整；不再叠加整页滚动容器         |
| 设置表单 | 模型、外观、通知、远程访问、决策模型等              | 统一受限宽度和分节结构；复杂模型配置使用明确的宽版变体              | 表单内容容器滚动；窄屏将字段和操作按语义顺序排列，错误信息跟随字段   |

跨模板共同遵循以下契约：

1. **外边距只有一个所有者。** 页面容器负责桌面约 24px、手机约 12–16px 的外边距，子页面不再重复增加整页 padding。工作台使用自己的满幅布局变体。
2. **标题层级稳定。** 应用标题栏负责窗口与全局导航；业务页头负责当前页标题、说明和主动作。任务页头由任务工作区持有，不重复套普通业务页头。
3. **工具栏顺序稳定。** 搜索、筛选、排序、视图切换和次要动作具有统一分组；手机按优先级换行或收入菜单，不随机改变位置。
4. **滚动边界唯一且可解释。** 不同时让壳层、整页和全高内部容器争夺滚动。工作台的多个局部滚动区不等于允许整个页面再建立一层重复滚动。
5. **加载、错误和空态复用骨架。** 保留页头、工具栏与相同宽度，避免状态改变时页面左右跳动或主操作移位。
6. **密度与排版按角色控制。** 常规区块间距优先 16px，主要分节 24px，紧凑条目使用 8px 或 12px；控件尺寸沿用统一变体，手机提供足够触摸区域。
7. **断点服务于可用空间。** 工作台和列表详情按内容容器宽度适配，不能只凭窗口断点假设侧栏、详情和检查器一定放得下。
8. **模板不拥有业务实体。** 列表选择、表单提交、查询和失效规则仍在所属领域；模板通过插槽、参数和回调组织显示。

应用级组合限定为有实际职责的页面容器、页头、工具栏、分节、列表详情和状态视图。普通分区、资源卡片与浮层采用不同外观层级，不统一套用带阴影或背景模糊的装饰卡片。

设置表单的常规宽度与宽版宽度由同一个类型化约定提供，不由各页自行散布 `max-w-3xl`、1040px 等值。具体值在代表页验证后确定，并覆盖中英文、字号设置与移动端；本阶段不以新数值直接覆盖全部旧页面。

## 14 键盘与可访问性

功能栏、项目侧栏、标题工具、标签栏、内容区和输入区形成可理解的焦点顺序。键盘焦点与任务工作区焦点同步，但单纯鼠标悬停不切换任务。

内容标签使用可访问的标签语义，选中状态、关闭按钮与完整名称可被辅助技术识别。文件行使用按钮及 `aria-expanded` 表达展开状态；不能仅通过点击非交互容器实现。

菜单与模态抽屉关闭后，焦点回到有效触发按钮。触发按钮已经消失时，回到同任务的稳定标题控件或相邻标签，不落在不可见 DOM 中。

手机摘要按模态对话框管理焦点、背景交互和遮罩；桌面摘要为非模态浮窗，不锁住主工作区。Escape 每次只关闭最上层界面。

沿用并检查现有快捷键映射，不把原型中的提示字符视为已经实现的新快捷键。新增快捷键必须有帮助入口，并处理平台或浏览器冲突。

## 16 兼容与迁移原则

1. 保留现有任务标识、会话历史、项目关联和运行状态，不因界面模型调整迁移用户业务数据。
2. 现有会话 Dock 标签中的任务映射为分屏中的任务工作区；没有同时显示的任务仍可从侧栏访问，不依赖重复的全局任务标签栏。
3. 已有内容面板的计划、浏览器、文件和侧聊视图保持兼容。新的后台进程与来源展示通过已有能力适配；不支持时显示真实限制，不返回假成功。
4. 原有持久化布局结构需要读取兼容与失效回退。若格式确需升级，另行定义版本、迁移与回滚，不直接覆写无法识别的旧值。
5. 桌面侧栏偏好与手机临时覆盖层分开管理。移动端显示变化不能覆盖桌面用户选择。
6. 自动展开资源与用户手动操作若继续保留，必须写入同一权威显示状态，并验证不会在任务切换或历史快照恢复时意外打开。
7. 回滚前端布局时不得终止仍在运行的任务、删除用户内容，或重置已有主题与其他无关偏好。

当前源码中，内容页已经按会话保存部分临时状态，而内容面板的显示与宽度仍存在全局偏好。实施时需要区分“任务自己的显示状态”和“用户通用宽度偏好”，不能仅换组件名称后保留相互覆盖的行为。

### 16.2 每批的进入与退出规则

- 开始前确认实际调用方、状态所有者、依赖方向和适用检查；存在移动或拆分时补充文件映射与公共接口说明。
- 已接受的颜色角色作为最终目标；第一批先修复存量组合的确定性缺陷，第二批再迁移强调范围与设置说明，避免将紧急可读性修复和全局风格改变混成一次变更。
- 模板逐页面接入。迁移某一页时不能直接删除所有旧页面依赖的壳层 padding 或滚动规则；未迁移页面保留明确的兼容路径。
- 共享组件改动验证其代表调用方，页面迁移验证该页面完整状态。未通过相关验证的批次不能声称完成，也不能用后续清理批次代替当前行为保护。
- 每批保留可回退的边界。回退界面不得删除用户数据、终止任务、清空偏好或依赖不兼容的持久化格式。
- 不增加固定文件行数、任意值数量或 Tailwind 使用比例的硬门槛。检查保护真实契约、生成结果、可读性、依赖边界与交互行为。
