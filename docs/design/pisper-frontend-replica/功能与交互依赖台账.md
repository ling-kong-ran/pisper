# 功能与交互依赖台账

本附录服务于前端1:1还原：区分可直接接入的能力、需补状态模型的交互以及依赖新服务的页面。**已有功能不代表视觉一致；功能语义不同也不表示无需调整外观。最终复刻目标以[主文](Pisper前端1比1还原差异与改造清单.md)与[复刻矩阵](replica-matrix.json)为准。**

此处P1/P2/P3为功能或状态风险排序，不替代主文的视觉改造顺序。共116项；未执行UI或应用测试，全部runtimeVerified=false。

### PN001 路由、懒加载与页面入口

状态：已有静态链；功能/状态优先级：none。

**建议：** 保留统一路由和懒加载机制，新增页面同步入口与能力判断。

**后续验收：**

- 深链接、刷新、返回与懒加载失败分别验收；新增重依赖不进入聊天首屏。

### PN007 加载、空态、错误的语义一致性

### PN008 并发操作通知的保留和恢复

状态：部分具备；功能/状态优先级：P2。

**现有实现：** Toast 有成功/错误/信息语义和本地化关闭，错误使用 foreground；App 持有单个 toast，notify 直接覆盖，Provider duration=2800ms。
