# 架构决策记录

跨多个模块、客户端、协议、存储格式或平台架构的设计选择，应在本目录留下简短的架构决策记录。小范围实现选择不需要单独建记录，但应在代码评审说明中写清楚原因。

## 记录要求

每条记录应包含以下内容：

```markdown
# 标题

- 状态：提议 / 已采纳 / 已替代 / 已废弃
- 日期：YYYY-MM-DD
- 影响范围：前端、Runtime、TUI、桌面端、Android、iOS 或发布流程

## 背景

说明问题、约束和需要解决的长期风险。

## 决策

说明采用的方案和依赖方向。

## 替代方案

列出考虑过的方案以及没有采用的原因。

## 影响

说明兼容性、迁移成本、性能、测试和运维影响。

## 迁移与回滚

说明分阶段迁移、兼容期、回滚条件和清理旧实现的时机。

## 复查条件

说明什么变化会触发重新评估。
```

记录应链接到相关代码、协议测试、迁移脚本或发布说明。状态发生变化时更新原记录，不要复制多份互相矛盾的结论。
