# 架构决策记录

改变长期依赖边界、公共协议、存储格式或平台架构的设计选择，应留下简短的架构决策记录。记录按需存入 `docs/architecture/<主题>.md`，不预建空目录；有关联专题文档时可以在原文维护决策并链接到代码。不要在多个位置复制同一决定。

文件数量不是是否需要独立记录的标准。遵循既定边界的局部移动、拆分或合并，只需在变更说明中填写下方结构变更记录；跨多个文件也不自动要求完整 ADR。结构治理可以独立成任务，无需附带新功能。

## 结构变更记录

- **问题与范围：** 当前职责混杂、错误归属或耦合的具体证据，以及本次治理的领域。
- **移动映射与公共接口：** 原路径到新路径、保留/移除的导出、受影响的调用方和客户端。
- **状态与依赖：** 谁拥有状态、持久化和生命周期，谁依赖谁；避免仅把原有共享 `this` 或整个 Runtime 对象搬到新文件。
- **验证：** 类型与行为测试、依赖检查、路由和懒加载、测试发现入口、源码守卫的变更及其替代保护。
- **迁移与回滚：** 存量调用方如何切换，是否影响协议/数据，如何按本次变更恢复；回滚不得覆盖既有用户修改。

拆分、保留共置和合并都需要以业务所有权、共同变化原因及接口成本解释。独立导出、没有共享状态或超过某个行数本身不构成拆分理由。一次结构变更应留下完整、可验证的调用链，不交付悬空导入或未接入执行入口的测试。

## 记录要求

每条记录应包含以下内容：

```markdown
# 标题

- 状态：提议 / 已采纳 / 已替代 / 已废弃
- 日期：YYYY-MM-DD
- 影响范围：前端、Runtime、TUI、桌面端、Android、iOS 或发布流程

## 背景

说明问题、约束和需要解决的长期风险。

## 决策

说明采用的方案和依赖方向。

## 替代方案

列出考虑过的方案以及没有采用的原因。

## 影响

说明兼容性、迁移成本、性能、测试和运维影响。

## 迁移与回滚

说明分阶段迁移、兼容期、回滚条件和清理旧实现的时机。

## 复查条件

说明什么变化会触发重新评估。
```

记录应链接到相关代码、协议测试、迁移脚本或发布说明，明确哪些内容已实现、哪些仍在迁移。源码守卫更新应说明原保护目标和替代验证，不能把“测试通过”单独作为架构合理的依据。状态发生变化时更新原记录；已知债务统一登记在 [`development-workflow.md`](development-workflow.md)，避免重复维护进度。


## 2026-10-15：Node 基线上的移动三屏布局

- 范围：移植 `feat/mobile-three-pane-layout` 与 `codex/fix-mobile-three-pane` 的移动端最终行为；不恢复 Rust Runtime，也不引入尚未完成的工作台改版。
- 归属：`app/mobile/MobileContextScreen` 是资产、文件变更、扩展和终端的 Feature 组装边界。通用 `MobileThreePane` 只接收插槽；文件选择边界见[系统文件选择](architecture/system-file-selection.md)。原分支重构过的路径映射到当前 Node 基线目录，不额外迁移全仓库。
- 状态与生命周期：移动壳只持有本地临时页签和屏幕状态；聊天运行状态由 ChatPage 提供只读投影；已打开的终端和插件面板在切屏时保留挂载。轻量布局在所有断点保持同一组件树，避免丢失未保存的表单；右屏业务视图继续懒加载，弹窗以视口定位。辅助页面经 DOM 插槽由聊天页 portal 渲染，继续使用原 SideChatProvider 和页签状态。
- 验证：`runtime/tests/mobile-shell-layout.test.mjs` 与 `npm run test:mobile:ui` 覆盖布局、状态保留和交互；Android/iOS 真机与发布构建分别按开发流程验收。源码守卫从旧底栏键盘样式迁移为顶部分页隐藏，浏览器测试保留其原本让输入区可见的行为目标。
- 回滚：一起恢复应用壳、移动上下文、Feature 公开接口、文案和对应测试；没有新增用户数据格式或持久化迁移。

## 2026-10：前端工作台职责迁移

- 范围与依据：采用[前端设计方案](superpowers/specs/2026-10-14-frontend-workbench-design.md)与[Node 基线实施计划](superpowers/plans/2026-10-14-node-frontend-workbench.md)。后端继续使用 release 的 Node Runtime，不改变 HTTP/SSE、代理引擎或发布渠道。
- 移动映射：原 `components/layout/SidebarRecentSessions` 的任务逻辑迁至 `features/chat/ProjectTaskList`，由 `public-navigation` 暴露；AppSidebar 只接收插槽。页面模板位于 `components/app`，不导入 Feature 实现。
- 状态：聊天领域按任务持有临时标签、草稿和资源阅读位置；Dock 只持有分屏位置与焦点。原生终端连接归应用级 TerminalProvider/registry，标签仅保存资源 ID，关闭视图不终止进程。公共页面偏好仍使用 `pageStateStorage`，未增加临时 URL、附件内容或日志的持久化。
- 生命周期：任务标题和附件入口通过工作区 DOM 插槽展示，编辑器状态仍由原任务持有。导航前显式通知保存阅读位置，因为 Dock 移除 DOM 早于 React 卸载。返回处理先交给当前弹层，再交给活动内容/列表详情层，不向浏览器历史插入临时条目。
- 依赖：应用壳通过轻量 `public-workspace` 事件打开焦点任务资源；终端公开轻量服务接口与懒加载视图两个入口。服务与组件导入均不隐式启动终端连接。
- 验证与回滚：统一入口见[开发流程](development-workflow.md#前端工作台验收入口)。迁移不修改用户数据格式；回滚应恢复同一批应用壳、Feature、模板和测试，不覆盖并存的发布说明改动，也不修改独立的 rust-runtime 分支。
