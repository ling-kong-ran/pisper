# 临时侧边聊天

- 状态：已采纳
- 日期：2026-09-27
- 影响范围：Web 聊天、Runtime 会话生命周期及增量 HTTP 接口；桌面和移动端复用 Web 界面，TUI 保留原有会话协议

## 背景

右侧辅助页面需要提供不打断主会话的临时问答。把它当作普通会话创建会污染左侧目录；只在前端设定过期时间又无法在关闭浏览器或 Runtime 重启后清理。

## 决策

每个主会话对应一个未过期的临时侧聊，从右侧“新增辅助页面”进入。侧聊只有消息、输入和必要的运行操作，不重复主会话页头。创建时继承工作目录、模型、思考等级和权限等运行偏好；消息记录、运行和停止均独立，不复制主会话历史，也不启动父会话的 Goal 或团队任务。

Runtime 持有侧聊归属与过期状态。首次创建、发送及运行结束更新活动时间，闲置 24 小时后清理。读取、打开面板和后台轮询不续期，正在运行及有活动子任务时不销毁。关闭辅助页面仅隐藏界面；过期前重新打开继续原侧聊，面板停留到过期时会显示“新开侧边聊天”，保留未发送的草稿；点击后创建空侧聊，不自动发送草稿。到期检查以服务端为准，避免断线残留的本地运行状态阻止过期提示。

侧聊复用现有会话创建、模型配置、SSE、停止、审批和文件追踪实现。新增服务只负责侧聊归属、并发创建与到期清理，通过窄接口调用会话生命周期。前端复用主聊天的单会话消息状态及流处理，侧聊摘要单独管理，不加入普通会话目录，也不改变当前主会话 ID。

服务端确认侧聊已消失或换成新 ID 后，前端释放旧正文和流所有权，并阻止迟到快照重新创建旧状态，避免继续轮询已过期会话。正常关闭面板或离开路由只释放观察者，不停止后台任务。

新增 `GET /api/sessions/:sessionId/side-chat` 和幂等的 `POST` 接口，通过父会话 ID 在服务端取得可继承配置。客户端不能借这些接口指定任意目录或提升权限。旧的聊天接口保留；过期 ID 必须拒绝执行，不能默默创建普通会话。

## 替代方案

- 单独实现模型请求和流式消息：会复制已有工具、审批与重连协议，容易产生行为差异。
- 只用前端定时器：关闭页面和重启后失效，不能保证过期清理。
- 复用普通新建会话入口再从 UI 隐藏：创建会激活主聊天，且其他客户端仍能看到临时会话。

## 影响与验证

不新增依赖和原生命令。桌面、Android 和 iOS 通过相同 Web 入口及 Runtime HTTP 接口使用功能；本次浏览器验证区分桌面和窄屏，不等同于原生构建或设备验收。TUI 不增加侧聊命令，普通会话目录和既有流协议保持兼容。

测试覆盖首次创建与重复创建、属性继承、独立消息、目录过滤、过期与重启、运行保护、旧 ID 拒绝，以及关闭重开、主会话草稿保留和手机宽度。服务与协议测试放在统一的 `runtime/tests/` 入口，浏览器回归由 `npm run test:ui` 调用隔离后端和本地模型 fixture。新增侧聊服务的窄接口及持久化元数据纳入 `tsconfig.jscheck.json`；既有 Runtime 其余未纳入的模块仍由真实服务和协议测试约束，不能将局部类型检查视为整个 Runtime 的类型覆盖。

## 迁移与回滚

新增带版本的侧聊元数据，不改普通会话格式语义。回滚前应停止临时侧聊运行并清理这些临时记录，避免旧版本将它们作为普通会话列出。清理只删除侧聊记录及附属状态，不撤销已经产生的工作区文件修改，也不删除父会话。

## 复查条件

需要每个主会话多个临时侧聊、跨设备恢复辅助页面布局、手动转存为普通会话，或更改闲置时长时，重新审视索引、归属与生命周期接口。
