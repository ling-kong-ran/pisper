# 会话整理状态与改动摘要

- 状态：已采纳
- 日期：2026-09-24
- 影响范围：Runtime、Web、桌面 WebView、Android/iOS WebView、TUI 会话目录协议

## 背景

会话列表原先只按文件修改时间排序。文件修改时间无法表示用户是否读过回复、Agent 是否失败，也无法支撑可恢复的归档。工作区 Git 状态是多个会话共享的，不能充当某个会话的改动数量。

## 决策

Runtime 的 `sessionMeta` 持有 `organization`：`pinned`、`archived`、`unread`、`failed` 和 `lastCompletedAt`。旧元数据读取时投影为默认值，不批量重写。Agent 轮次结算才设置未读；成功清除先前失败，失败保持需要处理。审批状态来自当前真实待处理审批项，优先于失败显示；不把已读等同于问题已解决。

`GET /api/sessions` 继续返回完整目录（包括归档），并在每个摘要中增量添加 `pinned`、`archived`、`unread`、`needsAttention`、`attentionReason`、`lastCompletedAt`。`PATCH /api/sessions/:sessionId/organization` 只接受可选布尔字段 `pinned`、`archived`、`read`，至少需要一个字段，返回完整更新后的会话摘要；`read:true` 清除未读。归档不删除会话，也不改变 `modified`。旧 Web/TUI 客户端可忽略新字段；新客户端对旧服务端的缺失字段按未置顶、未归档处理。

Runtime 的会话文件变更服务只从本会话写工具索引和原始快照计算净变更；`GET /api/sessions/:sessionId/change-summary` 返回 `status`、`changedFiles`、`pendingFiles`、`added`、`removed`、`unknownFiles`、`capped`。仅 `known` 允许展示准确数量；快照缺失、范围超限、索引被淘汰时返回 `partial` 或 `unavailable`，计数为 `null`。新会话创建时写入带起始工作区的空索引，以证明尚无写入时的零改动；旧会话无索引不能推断为零。Shell、扩展及其他未覆盖工具执行前持久标记为 `partial`，切换工作区后也不再用旧快照报告精确数量。50 个真实快照会话和最多 500 个空索引标记分别保留，避免空会话挤掉可撤销快照。

Web 聊天领域 API 提交整理操作并广播服务端确认的结果；侧栏、历史页和会话目录只投影同一 Runtime 数据。历史搜索覆盖归档与未归档，常规列表分开呈现；改动摘要仅在历史行进入视口后请求。会话页持有唯一的右侧上下文面板及其标签状态，内容随活动会话切换；Dock 仅承载主会话和用户主动打开的分屏，移动端单会话布局继续使用原宿主。上下文内容按需加载，关闭时释放其独占观察者。

会话重命名成功后，侧栏广播服务端确认的标题，打开的会话目录据此同步桌面标签、移动标签、会话标题和页面标题。目录加载按请求开始时的标题修订号协调结果：请求期间确认的重命名覆盖旧快照，即使初始化还在等待配置、目录尚为空也不会丢失；后发请求仍采用服务端目录，允许其他客户端的改名正常同步。确认记录只在当前聊天页面存活，删除会话时清除，不形成独立持久化标题源。回归覆盖初始化延迟、连续改名、后台会话与乱序响应。

左侧工作目录顺序独立于会话活跃度：首次沿用当前目录顺序，之后新目录追加底部；新建、更新或置顶会话只改变组内顺序。聊天领域 `workspace-order-store.ts` 持有本客户端的 `pisper-workspace-order` v1 偏好，顺序字段仅记录归一化的目录 key；侧栏从完整会话目录登记新目录，搜索、归档、最近条数限制与暂时空数据不清除原位置。刷新或重新打开后恢复相同顺序，消失的目录再次出现时仍使用原位置。该偏好适用于 Web 及桌面/移动 WebView，不修改 Runtime/TUI 协议；旧客户端忽略此存储项即可回滚。回归测试覆盖活跃度变化、过滤恢复、Windows 路径别名和持久化恢复。

项目重命名作为同一客户端导航偏好，在 v1 存储中增量增加可选 `names` 字段，按归一化目录 key 保存显示名称；旧数据只有 `order` 时仍恢复原顺序并使用目录名。侧栏项目行的重命名按钮及右键菜单提供入口，项目搜索和删除确认使用该名称，悬浮提示仍显示原路径。名称不为空、最多 120 字；取消不写入，菜单中的“恢复默认项目名称”移除别名。重命名只修改显示名称，不移动目录、不改会话所属目录或项目顺序，不同步到其他设备与 TUI。名称随刷新恢复，暂时隐藏的项目保留名称；回滚旧客户端仍可使用目录名和原有顺序。持久化写入失败时保持原名称并提示重试。验证包含 Windows 路径别名、旧存储、非法数据、恢复默认和存储失败回滚。

根目录 `/` 使用独立 key，Windows 盘根按小写盘符归一化。旧版若把 `/` 合并进“无工作区”而未保留独立顺序，升级后将其作为新发现的目录追加；原有其他目录顺序不变。

## 替代方案

- 由各客户端在本地存储置顶、归档和未读：跨 Web、桌面、移动和 TUI 的状态会分叉，因此未采用。
- 按文件 `modified` 推断未读或失败：重命名、设置变化和后台持久化都会误报，因此未采用。
- 用工作区 Git/SVN 差异显示每会话改动：不同会话的写入无法可靠归属，因此未采用。

## 影响

会话摘要协议仅增量添加字段；TUI 尚未消费组织状态，由 Serde 忽略扩展字段，并通过兼容测试确认新旧响应仍可读取既有导航信息。整理 PATCH 串行化并持久化；对尚未写盘的新会话先持久化最小会话文件。摘要计算有索引大小、文件数、文件大小和总读取预算，旧会话可能显示未知；界面不把未知渲染为零。相关测试位于 `runtime/tests/chat-session-organization.test.mjs`、`session-file-changes.test.mjs`、`session-organization-client.test.mjs` 和 `session-change-summary-route.test.mjs`。

## 迁移与回滚

无需离线迁移，旧字段和原会话文件格式保留。回滚前端可继续由旧客户端读取全量会话目录；回滚 Runtime 前端会失去新整理操作，已写入的 `organization` 字段仍留在元数据中，不覆盖用户会话内容。只有确认所有受支持客户端均可读取新字段后，才能考虑未来的协议清理；现阶段不删除旧字段。

## 复查条件

当会话目录需要服务端分页、跨设备同步，或文件改动索引的保留期限影响大量真实用户时，重新评估列表和摘要 API。若审批需要跨重启持久化，应为审批建立独立事实来源，再调整 `needsAttention` 投影。
