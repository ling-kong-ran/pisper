# 工作流图像节点与 FrameBaker 移植

- 状态：已采纳
- 日期：2026-09-27
- 影响范围：Web、Runtime 与共用 Web 客户端；TUI 保持 JSON 契约，不新增图像界面。

工作流画布用于组合步骤，游戏素材工作台用于交互式制作素材，两者是独立产品。旧工作台通过 `sprite-workbench-model.ts` 创建普通 DAG，会因画布改变而无法编辑；本次移除这层映射与 `workflows` 组件桥，不删除已有用户工作流。

## 所有权与依赖

- `shared/image-operations.mjs`：环境中立的图像设置与媒体输出契约；`workflow-image-nodes.mjs` 只增加 DAG 节点种类及命名适配。输出保留已有 `workflow-images` 格式标识，不含工作流 ID。
- `shared/image-frame-edits.mjs`：有序帧编辑协议；`shared/game-assets.mjs`：独立项目、任务和版本 1 存储契约。
- `ImageToolsPlugin`：固定绑定 workflow、workbench、agent 调用入口，只有 Agent 受工具开关控制，默认关闭。请求不能伪装其他调用入口。
- `ImageOperationService`：受控媒体加载、图像模型调用、分方向生成、本地处理及结果保存，不知道工作流或工作台的状态。
- `ImageAgentService`：Agent 调用、导入和工作区导出的生命周期所有者；关闭时拒绝新任务并等待在途操作结束，再释放媒体资源。
- `WorkflowImageNodeService`：将节点、前驱输出和输入值映射成插件调用；`WorkflowService` 继续拥有 DAG 调度、取消、运行与 ZIP。
- `GameAssetsService`：拥有独立项目、后台生成任务、取消、手工编辑版本与 `game-assets/game-assets.json` 持久化；不读取或更新工作流。各入口使用独立媒体目录，共享只读算法缓存和处理队列。
- `WorkflowImageProcessor`：短命 Worker、PNG/JPEG/WebP 解码与本地 WASM 推理；处理完成、取消和关闭后销毁。`shared/vendor/framebaker/` 保留移植函数来源和 MIT 许可。
- `src/features/game-assets/component-api.ts`：组件领域公开的窄桥。`CustomUiToolPage` 仅提供通用组件沙箱，业务规则不放基础 UI。

工作台生成、原帧和编辑后结果由服务持有，编辑器只持有未保存草稿。手工编辑始终从 `originalOutput` 重放；保存失败保留之前结果。Runtime 退出先取消领域任务，再关闭图像服务、Worker 和媒体存储。前端卸载不停止已启动的生成任务。

## 人工调帧

支持帧时间线、洋葱皮、平移/旋转/缩放/透明度/时长、排序/复制/删除以及擦除/恢复笔刷、撤销/重做。笔刷坐标对应原图，恢复使用原始透明度。`edit → export` 全程本地处理，不调用生成模型；保存原始输出与编辑列表便于反复调整和重启后继续。

人工变换保留原帧画布，越界部分裁切，不按自动包围盒重新居中。`shared/image-alpha-strokes.mjs` 的自包含纯函数由 Worker 和内置组件静态脚本共同使用，避免浏览器抗锯齿笔刷与保存后的透明度不一致。逐像素测试覆盖细斜线、恢复和边界。

## 生成质量

FrameBaker 默认一次生成单动作少量连续帧，Pisper 原先一次生成八方向乘多帧。现在直接复用其 `buildActionSheetPrompt` 和 `suggestActionSheetGrid`，每个动作、每个方向独立请求，保留原图风格并要求固定相机、全身安全边距、逐格帧顺序及首尾循环。默认四动作、八方向各四帧会调用图像模型 32 次；运行前明确显示数量，付费生成不自动重试。失败方向之前的成功结果保存在运行记录，仍可检查。

工作台上传源图的默认去背景使用本地 U²-Net small；缺少算法时只提示下载，不回退到颜色移除。复杂背景与黑色衣服等主体可能颜色相近，边缘连通不能避免误删，因此颜色移除只作为用户明确选择的纯色背景操作。受控生成图依然使用多色键、容差、软边和边缘连通。重复处理从 `originalReference` 开始，保留可恢复的原图。FrameBaker 并没有保证运动一致性的独立生成网络，其 rembg 默认完整 U²-Net。本次不把大模型或 Python/Bun 隐式装入 Pisper，也不将人物分件、骨骼绑定或 Qwen 语义分层宣称为八向生成的自动保证。

## 工作流包与数据

统一 ZIP 携带 DAG、节点参数、输入定义、默认素材以及图中实际需要的已下载算法及许可证。缺少必需本地算法时不生成假装可以离线运行的包。导入校验资源并为媒体重新分配 ID、创建草稿；模型密钥、工作目录和服务凭据不导出。算法属于独立共享缓存，模板提交失败时不会卸载其他工作流可复用的已校验资源。

节点设置是现有工作流 v2 格式的增量字段 `image`，图像输出独立 `version: 1`。服务端校验种类、有限值、媒体引用、图像像素与 ZIP 资源；客户端解析 `unknown` 后才能预览。旧客户端不能无损编辑新增节点，应在连接版本一致时使用。回滚不删除用户媒体、工作流或已下载算法。

## 验证范围

覆盖真实像素编解码、色键透明度、拆帧顺序、共同画布对齐、变换/图集导出、参数及错误边界、短命 Worker 取消、服务节点连接、部分生成失败与 ZIP 往返。浏览器验收验证模板直接进入画布、可修改节点、上传输入运行、节点结果预览和统一包导入导出。图像服务测试使用确定性合成响应；真实生成质量仍受用户选择模型影响。

桌面/Web 与 TUI 共用严格 JSON 接口；TUI 不增加图像编辑界面。移动端通过相同 Web 节点 UI 和服务器能力检查接入，移动尺寸浏览器测试不能替代 Android/iOS 真机内存与 WASM 验收。资源继续按固定 CDN 和 SHA-256 校验下载，安装包不携带可选模型。

## 独立组件桥与回滚

工作台通过 `game-assets.read`、`.write`、`.run` 权限访问 `/api/game-assets`，不接受任意 URL、Shell 或文件路径。Agent 文件导入限制在当前工作区的普通图片，媒体引用不能跨命名空间。组件预览无授权；路由入口按宿主 Worker/WASM 能力决定是否可用，不以工作流或 Agent 插件开关代替实际能力。

回滚需一起恢复领域服务、路由、桥、组件和注册入口；不得删除用户工作流或独立素材目录。先前带 `sprite-workbench` 标签的工作流仍作为普通工作流保留，不做持续双向同步。新增协议与服务进入 checkJs，行为覆盖独立持久化、关闭 Agent 插件时继续运行、媒体隔离、人工编辑重放与失败回滚；浏览器验收验证实际交互、导出与调用次数。

此前“同一工作流的两种视图”方案会让人工素材编辑依赖 DAG 拓扑，因此已被独立项目方案替代；底层处理仍共享，避免重复实现算法。未来新增视频工作台或改变图像资源协议时，应重新评估该领域接口与平台能力，而不是复制工作流状态。
