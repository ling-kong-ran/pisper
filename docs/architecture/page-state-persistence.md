# 页面状态持久化

- 状态：已采纳
- 日期：2026-09-28
- 影响范围：前端、Runtime、桌面端、Android、iOS

## 背景

本机 Runtime 使用随机回环端口。浏览器按源隔离 `localStorage`，因此仅写入浏览器的主题、组件显示和页面偏好会在重启后看似丢失。会话上下文还曾由旧布局模板控制初始显示，覆盖用户最后一次开关选择。

## 决策

页面通过 [`pageStateStorage`](../../src/lib/page-state-storage.ts) 读写状态：操作先更新当前源的 `localStorage`，再写入本机 Runtime。启动入口在加载应用 Store 前恢复白名单中的状态。Runtime 通过 [`/api/local/browser-preferences`](../../runtime/http/local-browser-preferences.mjs) 将其原子写入数据目录；移动代理在远程模式也把这一路径留在本机。白名单和大小限制由 [`shared/browser-preferences.mjs`](../../shared/browser-preferences.mjs) 统一约束。一次性会话请求、预览 URL 和凭据不进入此存储。

每个偏好键带递增修订号。当前源的 `sessionStorage` 暂存尚未确认的写入及其修订号；同源刷新若先读到 Runtime 的旧快照，会保留并重发较新的本地选择。Runtime 串行写入，拒绝比已保存修订号更旧的请求，避免迟到的普通请求或 `pagehide` beacon 覆盖新值。确认写入后清除对应暂存项。新随机端口无法读取旧源的浏览器存储，仍以 Runtime 快照恢复。单项值最多 512 KiB，全部值合计最多 2 MiB；HTTP 请求体另按 JSON 转义的最大开销设置有界上限。

读取与写入请求均有超时；初次迁移的补写在后台队列执行，不阻塞应用挂载。写入失败后按原修订号重试，期间的新操作优先，不会被失败批次中的旧值覆盖。

任务上下文开关、标签、资源阅读位置及各任务的实际内容宽度由聊天领域的任务工作区 Store 临时持有，首次关闭，本期不承诺跨刷新恢复。通用上下文宽度仍通过页面偏好保存，只作为新工作区的默认值，不再实时控制所有任务。旧持久化 `open` 字段保留兼容读取，但不覆盖新任务的默认关闭状态。会话布局模板与编辑画布已移除；聊天页只有观察到同一会话、同一有效开始时间的运行从进行中变为成功完成，且文件改动发生在本轮，才自动展开。目录里过时的 `streaming` 摘要接上历史完成快照不能算作本轮完成。

## 替代方案

只用 `localStorage` 无法跨随机端口恢复；给本机 Runtime 固定端口会引入端口冲突。直接把所有浏览器键写入 Runtime 会包含临时请求和潜在敏感数据，因此使用显式白名单。

## 影响

旧布局键 `pisper-chat-layout` 已从白名单退役，不再迁移或同步。读取旧 Runtime 快照时会忽略该键及其修订号，以免旧的大型布局数据阻断其他偏好恢复；成功恢复后会清除当前浏览器源中的旧键，Runtime 下次写入时清除文件中的旧键。旧版本的通用上下文宽度仍可迁移；新任务首次看到关闭的面板，不依据旧的全局显示状态打开临时资源。远程监听不提供本机偏好接口。存储服务的重启、容量边界、写入顺序及自动展开条件均有定向测试。

## 迁移与回滚

新版本首次启动时将当前浏览器源中已有、Runtime 尚未保存的白名单键补写至 Runtime；已有的 Runtime 值优先，但同源待确认日志中修订号较新的操作优先于旧快照。旧版偏好文件没有修订号时仍可读取，旧客户端未带修订号的写入由 Runtime 分配修订号。回滚旧版本不会删除其他 `localStorage` 偏好，但旧版本不读取 Runtime 的偏好文件。不要用回滚覆盖用户在新版中的选择。

`pisper-ui` 的 Zustand 内容版本 2 由 UI Store 管理，增加独立的 `uiFontSize`（默认 14、范围 11–16）和 `codeFontSize`（默认 12、范围 8–24），不改变 Runtime 偏好快照版本。旧 `fontScale` 的 small/default/large 分别恢复 13.5/14/14.5，以保留旧显示；新数字输入按整数提交。已有合法数值优先于旧档位，异常数值有界归一化。`fontScale` 保留为兼容投影，旧 setter 同时更新权威 UI 数值。正文与根 rem 仍为独立角色，字号输入中的半成品不写入页面状态。恢复默认同时重置两种字号；随机端口恢复复用现有白名单与修订号机制。

## 复查条件

`sessionStorage` 待确认日志只在同一浏览器源内有效；若关闭应用时最后一笔请求及 `pagehide` beacon 均未到达 Runtime，新随机端口无法恢复该笔操作。如果未来改为固定应用源、需要跨设备同步页面状态，或需保证异常退出前的最后一次操作必定持久化，应重新评估本机镜像和冲突规则。
