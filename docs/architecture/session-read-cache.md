# Rust 会话读取缓存

- 状态：已采纳
- 日期：2026-10-11
- 影响范围：Runtime、Web 和 TUI 的会话读取接口

## 背景

Rust 迁移后的会话定位调用完整目录扫描，列表随后再次打开全部日志。历史消息、模型、用量和文件改动等请求重复读取这些日志。旧 Node 实现中的目录缓存、并发去重和有界消息投影缓存未接入该链路，导致小会话的读取成本也随其他历史文件增长。

## 决策与状态归属

`AppState` 拥有 `SessionReadCache`。索引、文件指纹、同文件读取去重和缓存回收位于 `runtime-rs/src/session_read_cache.rs`；HTTP 和消息协议的组装仍在 `session_api.rs`，文件改动领域仅取得已解析的工作目录。没有移动供应商文件，也不把整个 Runtime 注入缓存。

- 定位 ID 只解析日志头，兼容原 sessions 根目录和工作区子目录。目录摘要扫描忽略正文、图片和工具输出，只提取名称、消息数量和活动时间。
- 摘要沿 Pi 当前分支借用条目，避免为统计消息数量而复制、序列化整段内容。
- 磁盘读取缓存依据文件大小、修改时间、创建时间失效；Unix 还比较设备、inode 和 ctime，Windows 从同一句柄读取元数据、卷序列号和完整 128 位文件标识，覆盖保留大小和时间的同名原子替换。Windows 文件系统不提供有效标识时直接读取，不复用缓存；缓存命中仍需打开句柄检查元数据，但不解析正文。读取期间检测到文件变化的结果不会发布为当前缓存。
- 同一文件的并发读取共用锁；不同文件不持有同一把读取锁。HTTP 的重型读取放在 blocking 线程池，避免占用异步请求工作线程。
- 消息缓存沿用旧实现的 8 项、24 MiB 估算预算，键同时包含文件指纹、分页参数和模型上下文窗口信息。页外只保留角色与时间锚点，避免大历史无法进入缓存；附件仍按整个会话的锚点定位，再输出目标页。
- 运行状态、审批、队列、计划、模型运行时选择和会话整理元数据每次重新投影。新生成的附件也在缓存之外读取，不能被静态消息缓存冻结。

## 兼容与回滚

没有更换用户数据路径、新增持久化格式或执行迁移。消息、分页游标、模型和用量字段保持现有契约。缓存只保留在进程内，重启自然失效；可以通过 revert 本次代码变更回滚，用户日志无需转换。

## 验证与复查条件

`session_read_cache` 与 `page_cache_tests` 的 Rust 测试覆盖并发去重、预算回收、分支、追加、重命名、工作目录、删除、原子替换及跨页附件归属。`scripts/smoke-rust-session-read-cache.mjs` 使用隔离进程和生成的历史，通过真实 HTTP 验证分页、缓存刷新和原始字节不变，已接入 `test:startup`。测试不使用个人会话或真实模型；耗时只作为报告，不作为固定 CI 门槛。

会话文件格式、分支语义、消息分页或附件归属规则改变时，必须同步复查缓存键与失效策略。缓存预算限制的是估算常驻数据，不包括正在响应的请求、解析中的日志和完整应用 RSS。

## 本机复测记录

2026-10-11，在同一台 macOS arm64 开发机、同一 Debug Runtime 和同一批 31 个会话（日志合计约 393 MiB，最大约 145 MiB、625 条展示记录）上复测：空会话消息接口由约 5.9 秒降到约 30 毫秒；缓存命中后的会话目录为 3–10 毫秒，之前为约 17–21 秒。最大会话的 40 条消息首次读取约 2.7 秒、缓存命中约 0.5 秒，之前约 8.5 秒。对应消息和 live 响应体大小保持约 9.6 MB / 12.3 MB，没有通过删减正文或工具输出提速。

这些数字区分首次解析与缓存命中，不是其他设备或 Release 构建的性能承诺。自动化回归使用合成数据，个人会话仅用于经用户授权的本机只读复测，不进入测试资产或提交。

## 标记、终端与 CLI 回归补充（2026-10-11）

标记列表此前逐个打开全部 JSONL 并递归克隆完整消息树；打标、改名还会创建会话引擎。现在轻量索引记录是否仍有有效标签，未标记的文件不进入消息树投影；标记投影复用文件戳缓存。树投影只构造预览需要的文本和工具名称，不序列化图片、思考内容及工具参数/输出，并用旧树实现作为测试对照。冷会话打标和改名使用同一创建/删除准入锁，驻留会话复用运行与修改租约，不初始化引擎，也不允许在运行中修改。语音、会话命令查询工作目录同样复用文件头。

本机 macOS、debug Runtime、31 个现有会话约 393 MiB，`GET /api/session-labels?limit=500` 只读测量：修复前 11.001 / 9.822 秒；修复后首次 3.199 秒、重复 0.0025 / 0.0026 秒；均返回 1 条标记、325 字节。冷读取仍需解析有标记的日志，不承诺任意体积历史首次读取均为毫秒级。没有为性能测试改写这些真实会话。

终端面板在查询目录前创建“启动中”标签，防止重复创建；目录失败明确报错，不回退到错误的默认目录。取消启动后，迟到的目录结果不能复活已关闭的标签。移动面板浏览器回归覆盖等待、重复点击、失败、取消和面板切换；macOS 原生验收另行检查真实 PTY 的输入输出、窗口尺寸及退出状态。

CLI 源码开发优先选取当前源码树的 Rust Runtime，缺失构建时给出构建指引；捆绑版本取组件清单，避免私有根包版本误导更新选择。Web 配置页使用 HashRouter 地址；非交互输入在创建 Runtime 前返回操作指引，避免进入 crossterm 后 panic。`smoke-rust-cli.mjs` 已接入启动闸门，使用隔离 HOME 验证帮助、doctor、工作目录、退出重启和错误输入；本机 PTY 另外验证模型夹具的真实 read 工具往返、流式中文回复、会话与模型选择器及退出。

`stage-rust-runtime.mjs` 从桌面打包入口提取同一套原生资源、许可证、文件摘要与版本清单生成，状态仅存在本次构建目录。桌面与独立 CLI 打包入口单向调用它；没有运行时依赖或用户数据迁移。独立 CLI 包含原生伴随进程与 Web 前端，不再调用已删除的 SEA 命令。签名与资源映射的原有桌面行为测试保留，新增隔离 CLI 暂存测试。Windows x64 使用同一打包代码与模拟命令边界测试；本轮实际构建/运行平台为 macOS arm64。npm 与移动端发布渠道仍未完成 Rust 迁移，不在本次本地打包中启用。

审查还修复两处持久化问题：临时侧聊过期时间漏减 Unix 时间基准，改用现有 chrono RFC3339 解析并覆盖 epoch、毫秒、闰日和非法日期；Skill 配置并发修改缺少事务锁，现由 AppState 持有领域写锁，覆盖安装、开关修改、卸载的读取—修改—原子替换。并发 HTTP 回归对 12 个技能同时修改两个独立字段，修复前复现失败，修复后要求全部请求成功且所有字段保留。

回滚应成组恢复缓存调用方、元数据租约、测试和资源打包公共函数；不需要修改用户存储格式或迁移目录。验证范围包括全量 Runtime/TUI 测试、启动 API 契约、前端检查、终端界面和 macOS 原生包。静态扫描和现有模块测试不等于所有真实供应商、硬件和平台都经过验收；未实现或未运行的平台不得标为通过。

### CLI 恢复会话的数字契约

真实 PTY 的 `pisper resume` 验收还复现了用量数字的跨端差异：Rust 历史投影把 Token 计数序列化成 `0.0`，而 TUI 的 `u64` 反序列化拒绝该 JSON 数字类型，导致历史恢复失败。Runtime 现按整数累计和输出计数，费用与命中率保留浮点；TUI 同时兼容旧 Runtime 的非负整数值浮点数字，明确拒绝负数、分数、字符串、null 和溢出。两侧各有契约测试，并已在真实终端恢复旧格式会话、显示原工具记录和中文回复、继续发送下一条消息。未命名会话在选择器中显示默认标题，避免空白列表项。
