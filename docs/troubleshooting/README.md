# 故障排查流程

本文档规定开发、测试和 CI 失败时的基本排查方式。具体平台问题继续记录在本目录或对应平台文档中，例如 `local-file-reveal.md`、`docs/mobile.md` 和 `docs/mobile-resume-network-verification.md`。

## 基本流程

1. 记录失败命令、源提交、Node/npm/Rust/平台版本、运行目标和首次失败时间。
2. 保留第一处错误及其上下文，不要只截取最后一行；检查退出码、错误堆栈、CI 任务状态和相关日志。
3. 先判断问题属于代码回归、环境差异、依赖/构建问题、时序竞态、权限问题还是外部服务故障。
4. 使用最小可复现命令或已有针对性测试验证假设，再扩大到完整测试或构建。
5. 遇到重复失败时停止盲目重试。修改后记录修改内容和新的观察结果，避免通过增加任意等待时间掩盖竞态。
6. 日志、截图和临时产物必须脱敏；不得上传 Token、Cookie、私钥、用户会话、完整个人路径或真实用户数据。
7. 修复后记录根因、验证范围、仍未验证的环境和是否需要补充测试、监控或文档。

## OpenAI 兼容端点返回 Cloudflare 403

当前源码中的 OpenAI Chat Completions、Responses、Azure OpenAI Responses 和 OpenAI SDK 视觉生成请求，在发送前统一移除 `X-Stainless-*` 诊断头，官方与第三方端点均适用。鉴权、User-Agent、组织/项目头及其他自定义头保持不变；非 OpenAI 协议和普通模型发现请求不受影响。过滤发生在 Runtime 的 SDK 请求边界，不替换进程全局 fetch，也不修改持久化配置。回滚时撤销聊天和视觉入口的过滤器接线即可。

这一兼容处理不能保证解除 Cloudflare 拦截。遇到 HTML 格式的 403 页面时，由端点管理员使用响应中的 Ray ID 查询安全事件，区分 IP/地区规则、机器人检测与 WAF 规则。页面显示来源 IP 或要求 Cookie，不足以确定封禁原因。不要提交 API Key、Cookie 或完整用户请求来排查。

## Windows Python 内存上涨、停止后进程仍在

0.5.68 的无 Bash 回退路径使用系统 PowerShell。旧实现取消或超时只终止
PowerShell，本次命令启动的 Python 等后代进程可能继续运行。该路径现已复用
Pi 的 Shell 进程管理，取消和超时按进程树回收，并复用输出管道释放逻辑。
回归测试使用真实解释器父子进程；Windows CI 通过实际系统 PowerShell 执行。
该修复不限制脚本本身的内存用量，也不能证明某个用户的 4 GB 占用由此引起。

排查时分别记录以下两种情况，不能把转述信息当成已验证事实：

- 仅打开应用、不发送消息就出现 Python：先确认是从托盘恢复窗口还是真正重启。
  桌面关闭按钮默认隐藏窗口，后台任务仍可运行；完全退出使用托盘的退出菜单。
  再检查已启用的计划任务、通道收到的消息、用户扩展，以及尚未消费的创建会话请求。
  创建会话请求可以带自动发送的提示词，并持久化到下次页面挂载。
- 发送消息或继续任务后才出现 Python：查看对应会话的命令工具调用。
  重复运行同一条高内存命令会再次产生占用；结束解释器进程不会自动暂停模型的后续重试。
  先通过会话的停止操作终止本轮，再判断是否有进程残留。

Runtime 初始化会暂停历史活跃 Goal/Team，并把运行中的子代理、工作流和计划任务记录标为中断；
已启用的计划任务仍会在新的到期时间运行，通道重连后仍可接收消息。
这些入口和用户扩展需要单独核实，不能仅凭未配置 MCP 就排除后台执行。
反馈至少保留 Python 的 PID、父 PID、启动时间、命令入口及当时的工具状态，分享前去除凭据和个人路径。
不得批量结束所有 Python 进程，也不要删除用户数据目录作为排查手段。

MCP 另有独立的生命周期修复：并发强制重连复用同一连接，禁用或退出等待创建中的连接取消，
创建失败释放客户端；单个会话取消等待不影响其他等待者。工具调用的配置超时按总耗时执行，
进度通知不再无限延长等待。这些修复不能用于解释没有配置 MCP 的用户故障。

## 长时间任务和 CI

发布、打包、完整测试和设备验证输出到日志文件时，应以较短间隔查看日志。出现非零退出码、错误堆栈、失败 CI 任务或 `##[error]` 后立即停止等待并诊断。

工作流正在修改发布分支或版本文件时，不要并行推送无关变更。先确认工作流状态、远程分支和暂存产物，再决定重试、清理或回滚。

## 报告格式

故障报告至少包含：

- 复现命令和最小输入
- 发生环境和源提交
- 实际结果与预期结果
- 首个错误及相关日志位置
- 已排除的原因
- 修复或临时规避方法
- 已验证平台和未验证平台
- 是否需要后续代码、测试、监控或文档变更
