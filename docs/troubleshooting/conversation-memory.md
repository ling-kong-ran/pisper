# 会话记忆与当前时间排查

适用范围：修复 issue [#14](https://github.com/ling-kong-ran/pisper/issues/14) 后的共享 Runtime。

## 现象与已确认问题

用户报告 Windows 上 GLM 推理模型的提取输出持续撞到 900 token 上限，并报告重启后无记忆、无用量。
源码确认旧提取上限为 900，模型错误及 JSON 解析失败均返回空候选，捕获层又吞掉异常。
这能解释“提取失败但没有诊断”，不能仅凭用户日志证明重启后的认证或响应丢失原因。

修复后，推理模型输出预算为 8192，普通模型为 2048，均不超过模型声明的上限；保持低推理等级及原有脱敏、逐字证据校验。
到达输出上限的结果不作为完整记忆使用，不自动重试或写入不完整 JSON。
提取并不针对每一条消息：仍需启用记忆工具、非隔离会话，并且用户消息满足已有的记忆意图条件。
例如“记住以后默认使用中文回答。”会触发，普通问候不会触发。
有效的空数组表示没有可提取内容；模型提取不会绕过原有置信度审核规则。

## 诊断

Runtime warning 日志使用 `[memory] capture failed` 前缀，只记录固定 `code` 与会话 ID 的 12 位 SHA-256 前缀。
不记录用户原文、证据、路径、凭据、SDK 错误或响应正文。会话哈希仅用于在同一环境关联重复故障。

| code | 含义与排查方向 |
| --- | --- |
| `model_unavailable` | 当前模型或 ModelRuntime 不可用，检查模型连接配置 |
| `model_error` | 调用抛错或模型返回失败，检查对应连接是否可用；不把 SDK 原文写入日志 |
| `token_limit` | 输出截断，检查模型输出上限及推理预算 |
| `empty_response` | 调用结束但没有文字正文，含仅输出思考的情况 |
| `invalid_response` | 正文不含可解析的候选 JSON 数组 |
| `timeout` | 初始化或请求等待超过两分钟，本次提取取消 |
| `usage_write_failed` | 用量写盘失败，已提取候选仍继续按正常流程入库 |
| `capture_failed` | 初始化、记忆存储等捕获步骤失败 |

失败响应提供用量时仍记入 `memory:` 账本；没有用量时不伪造统计。
正常退出取消在途捕获，不写入晚到响应，也不把退出取消作为故障 warning。
不要通过编辑安装目录的编译产物、删除记忆数据库或提供真实凭据来验证问题。

## 时间上下文

每轮 `before_agent_start` 将当前 UTC 时间、本地时间与运行环境时区加入 Runtime 系统提示，包含恢复旧会话及子代理。
时钟仅出现在真实请求的提示末尾；工具选择、提示预览与时钟之前的提示前缀保持稳定。
旧 Runtime 块被替换，不会累积多个时钟；历史会话内容与时间戳不改写。
这是 Runtime 所在设备的时钟和时区；远程连接使用服务端时钟，不推测浏览器所在时区。

## 实现边界与验证

文件不移动。`conversation-memory.mjs` 负责模型预算、结果归一化和证据校验；
`ConversationMemoryCapture` 持有捕获任务、超时与取消，通过模型访问器、初始化等待、记忆存储及用量记录的窄接口接线。
Runtime 在关闭记忆库之前停止并等待捕获任务。`abortable-memory-operation.mjs` 只终止当前等待，不取消共享初始化。
每轮时间由既有 `pisperPromptExtension` 注入，沿用 Pi 的请求投影，不回写历史 system 消息。

测试入口为 `runtime/tests/conversation-memory-capture.test.mjs`、`local-memory-runtime.test.mjs` 和 `pisper-system-prompt.test.mjs`。
覆盖输出预算、截断/空正文/错误/非法 JSON、正常空候选、秘密脱敏、用量失败、超时、关闭、晚到结果，
以及从同一临时目录重建 Runtime 后通过本地 GLM 兼容 SSE 服务取得正文、用量和持久化记忆。
日期测试覆盖旧会话三天后恢复、跨 UTC 日界和历史不变。
真实 Z.ai 凭据与用户设备未参与自动化测试。

共享 Runtime 行为覆盖 Web、TUI、桌面、Android 与 iOS；不新增原生桥接、资源、权限或平台分支。
公共 HTTP/SSE 形状、SQLite schema、已存记忆与候选的信任规则不变，无数据迁移。
取消等待辅助模块纳入 `checkJs`；其余存量 Runtime 模块尚未整体纳入，边界由上述行为与集成测试约束，不宣称全 Runtime 已获类型检查。
回滚使用正常代码回滚与发布流程，不修改或清空用户的记忆数据库。
