# 让其他 Agent 调用 Pisper

Pisper 的**内置 MCP 服务**把当前正在运行的 Pisper 能力提供给同一台电脑上的其他 Agent。它与在 Pisper 中添加外部 MCP 服务是两个方向：前者让外部 Agent 连接 Pisper，后者让 Pisper 连接别的服务。

此功能默认关闭。打开 Pisper 的 **MCP 页面 → 内置 MCP 服务**，开启服务后复制连接配置，粘贴到外部 Agent 的 MCP 客户端设置。需要先让 Pisper Runtime 保持运行。Android / iOS 的本机 Runtime 目前不提供此服务。

## 连接

外部客户端必须支持 **MCP Streamable HTTP** 和自定义 `Authorization` 请求头。服务仅监听本机回环地址；默认连接地址为 `http://127.0.0.1:5175/mcp`，不能从另一台电脑或手机直接连接。请以 Pisper 界面显示的实际地址为准。

下面是通用配置示意。各客户端的配置字段可能不同，请将界面提供的地址与令牌填入该客户端的 MCP 服务配置：

```json
{
  "mcpServers": {
    "pisper": {
      "url": "http://127.0.0.1:5175/mcp",
      "headers": {
        "Authorization": "Bearer <从 Pisper 复制的令牌>"
      }
    }
  }
}
```

连接失败时，先确认 Pisper 仍在运行，内置服务状态为“可连接”，且客户端使用了 Streamable HTTP 和完整的 `Bearer ` 前缀。如果 5175 端口被其他程序占用，Pisper 会在服务状态中显示错误；关闭占用端口的程序后，重新切换此开关以重试。

## 可用能力

当前提供 21 个工具。外部 Agent 可以发现工具及参数，再根据任务调用：

| 类别 | 能力 |
| --- | --- |
| 会话与消息 | 列出会话、读取消息或实时状态、新建及重命名会话、发送消息、查询运行结果、停止当前回合 |
| 目标 | 查看目标状态、暂停目标 |
| 记忆 | 检索相关记忆 |
| 工作流与定时任务 | 列出和运行工作流、查看或停止工作流运行、列出和立即运行已有定时任务 |
| 状态与资料 | 查看运行能力和今日用量、搜索资产、查看会话文件改动 |

`pisper_send_message` 会立即返回运行 ID。外部 Agent 应使用 `pisper_get_run` 查询结果；若返回等待审批，需要回到 Pisper 处理。会话里的工具执行仍遵守该会话已有的权限和审批设置。工作流和定时任务沿用各自的既有执行规则。此接口不提供直接读取 Provider 密钥、批准权限请求或任意调用 Pisper 内部方法的工具。

## 令牌与关闭

**持有连接令牌的本机程序可以调用全部已开放工具**，包括读取会话和记忆、发送消息及触发工作流。只把令牌交给可信的本机客户端，不要把含令牌的配置提交到仓库、放进截图、日志或聊天记录。令牌与开关保存在 Pisper 的 Agent 数据目录；使用 `PISPER_AGENT_DIR` 时随该目录迁移。

在 MCP 页面关闭内置服务会停止监听，并中止由该服务发起、仍在运行的会话回合。再次开启可继续使用。怀疑令牌泄露时，在同一页面轮换令牌，然后更新每个客户端的配置；旧令牌会立即失效，已有连接会断开。开关状态会在重启后保留，若此前开启，Pisper Runtime 启动后会重新监听。

这是一项本机集成能力。桌面远程访问的设备令牌不能替代内置 MCP 令牌，内置 MCP 服务也不会经桌面远程访问对外开放。
